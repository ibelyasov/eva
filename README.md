# JediKit

Русскоязычные Agent Skill для Hermes Agent: что и как Hermes делает в личной жизни и работе владельца по методологии каждой темы. Сейчас это личная продуктивность — пять скиллов:

- **`jedikit-tasks`** ведёт задачи в [SingularityApp](https://singularity-app.com) по методу «Джедайских техник» Максима Дорофеева и исследованиям работы с задачами: Capture, Triage, следующий шаг проекта, Daily open, Daily close, Weekly и разбор Inbox debt. Фокус-лист составляется без календаря и проверки вместимости; разделы и теги поддерживаются, kanban — нет ([ADR 0007](docs/adr/0007-no-kanban.md)).
- **`jedikit-habits`** ведёт поведенческие эксперименты и ритуалы в [Habitify](https://habitify.me): план эксперимента в заметке привычки, отметки, помощь при тяге и обзоры. Ритуал объединяет привычки в Области Habitify; новое поведение проверяется одним экспериментом за раз. При признаках клинического риска Safety-стоп направляет к специалисту.
- **`jedikit-calendar`** ведёт личный Google Calendar: показывает день и неделю, создаёт, переносит и удаляет События, ведёт Распорядок по просьбе пользователя. Читает выбранные календари, пишет в один; рабочий Outlook не управляется.
- **`jedikit-planning`** составляет План дня поверх Фокус-листа: проверяет вместимость по свободным окнам и предлагает Брони для важных задач. Бронь ссылается на задачу, не закрывает её. Daily open остаётся в `jedikit-tasks`; План дня — следующая команда.
- **`jedikit`** всегда загружен: несёт компактную карту скиллов и предпочтения владельца из `skills.config`, которые читают остальные скиллы. По запросу объясняет возможности, словарь и карту команд, помогает выбрать скилл и следующий шаг. Навигатор только читает и не выполняет сценарии других скиллов.

Решение всегда остаётся за пользователем. Полная явная команда выполняется сразу, включая несколько названных записей на разных провайдерах. Одиночное предложение агента — одна строка и «да»; собранный агентом набор — один общий Preview и подтверждение. Безвозвратная потеря данных Habitify (удаление привычки, области, удаление/отмена отметок) всегда требует однострочного подтверждения. Однозначное удаление События выполняется сразу: оно остаётся 30 дней в корзине Google, восстановление доступно только в интерфейсе Google. Группа выполняется последовательно, останавливается на первой ошибке с отчётом applied/unverified/unapplied и не откатывается автоматически. После каждой записи — Read-back ([ADR 0014](docs/adr/0014-confirmations.md)). Фоновые запуски только читают. Предпочтения задаются один раз при подключении ([Setup](#setup)), память агента хранит только пометки объектов ([ADR 0017](docs/adr/0017-declarative-preferences.md)). Термины — в [CONTEXT.md](CONTEXT.md), решения — в [docs/adr/](docs/adr/).

Проект в ранней версии. Версии — теги и commit SHA на [странице релизов](https://github.com/ibelyasov/jedikit/releases); публикация версии — отдельное решение владельца.

## Установка

JediKit работает в [Hermes Agent](https://hermes-agent.nousresearch.com/). Установка добавляет только инструкции пяти скиллов; доступ к SingularityApp, Habitify и Google Calendar, а также внешний скилл `grill-me` настраиваются в Hermes отдельно — см. [«Что нужно от Hermes»](#что-нужно-от-hermes). Предпочтения и задания приглашений Потребитель задаёт по разделу [Setup](#setup). Ставьте закреплённую ревизию: полный 40-символьный commit SHA каждой версии указан на её [странице релиза](https://github.com/ibelyasov/jedikit/releases).

Каталог `skills/` закреплённой ревизии подключается в профильном `config.yaml` Hermes. Ревизию закрепляет источник каталога — checkout на нужном commit SHA или Nix input с этим SHA; у владельца так подключает clanwright.

```yaml
skills:
  external_dirs:
    - /path/to/jedikit/skills
  auto_load:
    - jedikit
  config:
    jedikit:      # значения — раздел Setup
```

Скиллы становятся обычными скиллами Hermes: имена `jedikit`, `jedikit-tasks`, `jedikit-habits`, `jedikit-calendar`, `jedikit-planning`; имя и начало описания каждого видны модели в индексе скиллов, явный вызов — `/jedikit-tasks` и т. д. Соседний скилл загружается по голому имени: `skill_view(name="jedikit-calendar")`. Одноимённая копия скилла в другом каталоге Hermes может затенить закреплённую — не держите таких копий. Hermes не защищает внешний каталог от записи: держите его неизменяемым средствами системы, например в Nix store. Подробности — [досье Hermes](research/platforms/hermes.md).

## Что нужно от Hermes

JediKit задаёт поведение скиллов и ожидания к инструментам. Hermes Agent загружает скиллы и вызывает инструменты. Всё остальное для Hermes обеспечивает Потребитель — репозиторий, который подключает JediKit к Hermes (у владельца это clanwright): выбирает, подключает и реализует инструменты и MCP по этому контракту, отвечает за окружение и песочницу, доступы, предпочтения и задания приглашений по разделу [Setup](#setup), расписания и доставку, характер и самообучение агента, всё, что работает без модели, включение скиллов и развёртывание. Если сценарию нужен инструмент, которого у Hermes нет, JediKit добавляет ожидание в `tools.json` или в этот раздел. Новую потребность Потребитель передаёт issue в этот репозиторий — рамкой задачи, а не спецификацией скилла ([ADR 0016](docs/adr/0016-consumer-boundary.md)).

Ожидаемые операции перечислены в [`skills/jedikit-tasks/tools.json`](skills/jedikit-tasks/tools.json) (35 операций), [`skills/jedikit-habits/tools.json`](skills/jedikit-habits/tools.json) (23 операции) и [`skills/jedikit-calendar/tools.json`](skills/jedikit-calendar/tools.json) (7 операций). У каждой операции указаны MCP-сервер, базовое имя и доступ `read` или `write`; у Habitify и Google Calendar ещё обязательные аргументы `required`. Агент вызывает их как `mcp__<server>__<base_name>`, где `-` и другие символы вне `[A-Za-z0-9_]` заменены на `_`.

**MCP-серверы:**

- **`singularity`** — официальный hosted MCP SingularityApp `https://mcp.singularity-app.com/mcp`; OAuth проводит Hermes.
- **`habitify_read`** и **`habitify`** — чтения и записи Habitify по официальному REST/OpenAPI v2 через доверенный адаптер. API-ключ хранится только у адаптера, агент его не видит. Скилл рассчитывает на такую форму ответа: ошибка — `isError: true` и HTTP-код в тексте как `status code NNN`; успех — без `isError`, тело ответа Habitify как JSON в тексте, пустой текст — успех без тела (`204`). Официальный Habitify MCP не подходит: в нём нет создания и изменения привычек, заметок и архивации ([ADR 0001](docs/adr/0001-habitify-via-rest.md), [справка инструментов](skills/jedikit-habits/references/tools.md)).
- **`google_calendar`** — Google Calendar с базовыми именами `list-calendars`, `list-events`, `get-event`, `get-current-time`, `create-event`, `update-event`, `delete-event`; у владельца это `nspady/google-calendar-mcp` `v2.7.0` ([ADR 0009](docs/adr/0009-separate-calendar-skill.md), [контракт инструментов](skills/jedikit-calendar/tools.json)).

**Конфигурация Hermes** (нужен Hermes v0.21.6 или новее; механика проверена по его source):

- `skills.external_dirs` — каталог `skills/` закреплённой ревизии.
- `skills.auto_load` содержит `jedikit`. Hermes загружает навигатор в каждую сессию и добавляет после его текста блок значений `skills.config`; остальные скиллы читают предпочтения из этого блока. Обычный `skill_view` значения не подставляет, поэтому без `auto_load` предпочтений в разговоре нет.
- `skills.config` — в профильном `config.yaml`: resolver Hermes v0.21.6 читает именно этот файл, managed overlay `/etc/hermes/config.yaml` его не заменяет. Ключи и значения — [Setup](#setup).
- Блок значений создаётся вместе с экземпляром агента. После изменения `skills.config` или `skills.auto_load` нужен новый экземпляр агента — перезапустите gateway: уже работающий агент Telegram сохраняет прежний блок.
- `timezone` Хоста согласован с `jedikit.timezone`: по нему считается cron.

**Toolsets и скиллы Hermes:**

- `skills` — `skills_list` и `skill_view` для загрузки скиллов и их `references/`.
- `clarify` — вопросы о недостающих полях и карточки согласия «Да»/«Нет» ([ADR 0013](docs/adr/0013-clarification.md), [ADR 0014](docs/adr/0014-confirmations.md)).
- `memory` — только пометки объектов, по одной записи на скилл: Режимы поддерева Областей и Папок SingularityApp (`JediKit tasks:`) и Ритуалы — Области Habitify с первой привычкой (`JediKit habits:`). Скилл-владелец пишет их по ходу работы; предпочтения в `memory` не хранятся ([ADR 0006](docs/adr/0006-memory-holds-object-marks.md), [ADR 0017](docs/adr/0017-declarative-preferences.md)).
- `cronjob` в разговоре не нужен: скиллы задания не создают и не меняют. Задания приглашений создаёт и сопровождает Потребитель — см. [«Приглашения»](#приглашения) ([ADR 0003](docs/adr/0003-no-unattended-writes.md)).
- Tool Search не обязателен: видимый MCP-инструмент скилл вызывает по имени, а при включённом Tool Search находит отложенные schemas через `tool_search` и `tool_describe` и вызывает через `tool_call`.
- **`grill-me`** — внешний скилл для редкого глубокого уточнения намерения (есть среди официальных optional skills Hermes). Если его нет, JediKit называет требование и рекомендует установить его; своё интервью не проводит.

`jedikit-planning` использует `jedikit-tasks`, `jedikit-calendar`, `jedikit-habits` и их инструменты; своего провайдера и `tools.json` у него нет. `jedikit` объявляет ключи предпочтений и требует остальные скиллы JediKit; своего `tools.json` у него нет.

Пакет не объявляет MCP-серверы и секреты ([ADR 0005](docs/adr/0005-hermes-host-connections.md)). Если нужных операций нет, скилл называет недостающие базовые имена и рекомендует подключить их в Hermes. Ни один скилл ничего не устанавливает и не настраивает подключения. Нужны также соответствующие права и тарифы провайдеров ([SingularityApp](research/providers/singularity.md), [Habitify](research/providers/habitify.md), [Google Calendar](research/providers/google-calendar.md)).

## Setup

Одноразовый setup при подключении: агент Потребителя проводит его с владельцем, затем Потребитель записывает предпочтения в `skills.config` и создаёт задания приглашений. В чате Hermes отдельного setup нет. Просьбу изменить предпочтение в чате скилл не выполняет: называет ключ и новое значение для Потребителя и при желании пользователя применяет его только в текущем разговоре. Решение — [ADR 0017](docs/adr/0017-declarative-preferences.md), основания рекомендаций с источниками — [досье setup](research/setup.md).

### Порядок диалога

1. **Прочитать известное.** Агент сам узнаёт то, что доступно чтением: timezone Хоста, календари, аккаунты, права и `defaultReminders` (`list-calendars`), наличие поддеревьев Когда-нибудь. Уже известное не переспрашивает; технические поля и ID у человека не просит.
2. **Спросить только факты о человеке** — то, что знает лишь он: подъём и отбой, начало и конец работы, рабочие дни, дорога, фиксированные встречи и обязательные утренние и вечерние дела, известная усталость в каком-то окне. Не спрашивать «когда вам удобно».
3. **Вывести рекомендацию** по таблицам ниже. Цели («хочу вставать в 6:30») — не действующие якоря: рекомендация опирается на текущий распорядок.
4. **Обсудить текстом** весь набор: значение, основание с уровнем, альтернатива. Человек может поправить любой пункт.
5. **Одно подтверждение** всего набора. Затем Потребитель записывает значения, создаёт задания и перезапускает gateway.

Факт, без которого ключ не вывести, можно оставить незаданным: действует значение из столбца «Если не задан», а если его нет и сценарию значение нужно, скилл спросит в разговоре и назовёт ключ для Потребителя.

**Уровни оснований:**

| Уровень | Смысл |
| --- | --- |
| ACAD | Научное исследование; поддерживает компонент (конкретный cue, мониторинг, внешнее напоминание), но не конкретное число или расписание |
| AUTH | Положение Максима Дорофеева: атрибуция метода, а не доказанная эффективность |
| COMM | Практика или опыт сообщества; не норма |
| VENDOR | Контракт продукта (Hermes, Google); SRC — прочитан source |
| ЭВРИСТИКА | Практическое предложение JediKit без прямой проверки именно этого значения |

### Предпочтения

Ключи объявлены в `metadata.hermes.config` навигатора `jedikit`; значения задаются вложенно под `skills.config`. Других ключей нет.

| Ключ | Формат | Если не задан | Рекомендация или правило вывода | Факты о человеке | Уровень |
| --- | --- | --- | --- | --- | --- |
| `jedikit.timezone` | IANA timezone | Скилл спросит, когда нужна дата | Домашний пояс, по которому человек ведёт обычный день; не язык, не пояс сервера или календаря. Согласовать с `timezone` Хоста | Город или пояс обычного дня; при поездках — сменился ли распорядок | VENDOR |
| `jedikit.tasks.workdays` | Список `mon`…`sun` | Режимы `рабочие дни`/`личные дни` неприменимы, скилл спросит | Фактические рабочие дни; Пн–Пт — только при таком режиме. Фильтр Режимов поддерева, а не запрет личных задач в выходные. Праздники и разовые смены не задаются | Обычные рабочие дни, сменный график | ЭВРИСТИКА |
| `jedikit.habits.names` | `exact` или `neutral` | Скилл спросит при создании чувствительной привычки | `neutral`: для чувствительных тем — нейтральные, понятные самому человеку названия; обычным действиям эвфемизм не нужен; явно выбранное имя сильнее | Нет блокирующих; при сомнении — видит ли кто-то экран и уведомления. Саму тему не выяснять | ЭВРИСТИКА |
| `jedikit.calendar.write_account` | Nickname аккаунта Google, `^[a-z0-9_-]{1,64}$` | Единственный подключённый аккаунт; при нескольких скилл спросит | Аккаунт личного календаря | Какой аккаунт личный — только если их несколько | VENDOR |
| `jedikit.calendar.write_calendar` | ID календаря | `primary` | Личный `primary` с правом записи; другой существующий личный календарь — если владелец отделяет Брони и Распорядок. Должен входить в календари чтения | Нет: ID и права агент читает | VENDOR |
| `jedikit.calendar.read_calendars` | Список `<account>:<calendarId>` | Все видимые календари | Не задавать (все видимые); явный список — если есть посторонние или справочные календари. Недоступные обязательства (рабочий Outlook) назвать владельцу: Свободные окна их не учитывают | Какие обязательства не попадают в доступные календари | VENDOR, ЭВРИСТИКА |
| `jedikit.calendar.day_bounds` | `HH:MM-HH:MM`, через полночь допустимо | Скилл спросит, когда нужны Свободные окна | Начало — подъём плюс обязательная утренняя часть; конец — отбой минус защищаемая подготовка ко сну. Рабочие часы — не границы личного дня | Подъём, отбой, обязательные утренние и вечерние дела, дорога, семейные обязанности | ЭВРИСТИКА |
| `jedikit.calendar.gap_minutes` | Целое число минут | 0, скилл показывает это в результате | 15 на обычный переход; больше по фактической дороге и подготовке; 0 — только для действительно бесшовных переходов. Зазор не создаёт записей | Типичная дорога и подготовка между делами | ЭВРИСТИКА; ACAD косвенно (planning fallacy) |
| `jedikit.calendar.reminders.events` | `calendar`, `none` или набор через запятую: `popup 30`, `popup 30, email 1440` | `calendar` | Показать реальные `defaultReminders`; если они не помогают подготовиться — `popup 30`; при дороге — раньше на её длительность | Подготовка, дорога, уже используемые уведомления | VENDOR (механика), ACAD (внешние cues), ЭВРИСТИКА (минуты) |
| `jedikit.calendar.reminders.bookings` | То же | `calendar` | `none`, если человек следует Плану дня; `popup 5` или `popup 0`, если начало Брони забывается | Забывает ли начинать выбранное | ЭВРИСТИКА |
| `jedikit.calendar.reminders.routine` | То же | `calendar` | `none` при устойчивом заметном cue; `popup 0` для нового действия без другого сигнала (будильник, Habitify) | Есть ли устойчивый сигнал | ACAD косвенно, ЭВРИСТИКА |

Hermes печатает значения Python `str()`; пустые и falsey (`0`, `false`, `[]`, `''`) он показывает как `(not set)` — для этих ключей это то же, что «не задан». Пример профильного `config.yaml` (значения вымышлены):

```yaml
timezone: Europe/Moscow          # timezone Хоста, по нему считается cron
skills:
  external_dirs:
    - /nix/store/<hash>-jedikit/skills
  auto_load:
    - jedikit
  config:
    jedikit:
      timezone: Europe/Moscow
      tasks:
        workdays: [mon, tue, wed, thu, fri]
      habits:
        names: neutral
      calendar:
        write_account: personal
        write_calendar: primary
        read_calendars:
          - personal:primary
          - personal:family123@group.calendar.google.com
        day_bounds: "07:30-22:30"
        gap_minutes: 15
        reminders:
          events: popup 30
          bookings: none
          routine: none
```

Агент видит блок так:

```text
[Skill config (from ~/.hermes/config.yaml):
  jedikit.timezone = Europe/Moscow
  jedikit.tasks.workdays = ['mon', 'tue', 'wed', 'thu', 'fri']
  ...
]
```

### Что setup не задаёт

- **Пометки объектов** — Режимы поддерева Областей и Папок SingularityApp и Ритуалы Habitify. Они возникают вместе с объектами: когда сценарию не хватает пометки, скилл-владелец спрашивает с рекомендацией и сохраняет ответ в `memory`.
- **Создание Областей** SingularityApp и Habitify — тоже по ходу работы (Capture, Triage, Daily), не анкетой.
- **Дату обзора эксперимента** — она живёт в Плане эксперимента.

### Приглашения

Приглашения к обзорам — задания cron Хоста. Их создаёт и сопровождает Потребитель; скиллы их не создают и не меняют. Базовый набор — **одно утреннее задание** незадолго до Daily open, состав которого зависит от даты.

| Часть | Рекомендация | Уровень |
| --- | --- | --- |
| Daily open | В начале первого доступного блока действий: при стабильной работе — у её начала, после дороги и подготовки. 5–10 минут, затем при необходимости План дня. Приглашение в рабочие дни; в личные — если там есть выбранные дела | AUTH (регулярный Daily), ACAD (конкретный cue), ЭВРИСТИКА (время и минуты) |
| Календарная часть | В том же сообщении, примерно за 10 минут до Daily open. Если первое обязательство раньше — сдвинуть по подготовке и дороге. План дня — после Daily open в разговоре: до выбора Фокус-листа вместимость не известна | ЭВРИСТИКА; ACAD косвенно |
| Weekly | Первый рабочий день, первый защищаемый интервал у начала работы; 30–45 минут на старт. При постоянной утренней встрече — следующее пригодное окно. Альтернатива — бодрое окно последнего рабочего дня | AUTH (день), ЭВРИСТИКА (время, минуты, альтернатива) |
| Когда-нибудь | При первом Weekly месяца отдельным модулем ещё 15–30 минут; без поддеревьев Когда-нибудь не нужен. Не заменяет Weekly | Ежемесячность — контракт JediKit; совмещение и минуты — ЭВРИСТИКА |
| Обзор эксперимента | В утреннем сообщении — только число экспериментов с наступившей датой обзора; дату задаёт План эксперимента (Активный — через неделю, Поддержание — через месяц). Сам обзор 5–10 минут в разговоре | Контракт JediKit; ACAD косвенно (мониторинг); ЭВРИСТИКА (минуты) |
| Daily close | По умолчанию без приглашения. Отдельное задание за 5–10 минут до конца работы — если к вечеру теряются обязательства, остаются неразобранные остатки или работа не отпускает. Гвоздодёр перед сном — без задания | ЭВРИСТИКА; ACAD косвенно; AUTH (Гвоздодёр) |

Одно cron-выражение задаёт одно время: если в личные дни нужен другой час, это отдельное задание; Daily close — тоже отдельное.

**Шаблон утреннего задания:**

| Поле | Значение |
| --- | --- |
| `name` | Уникальное, напр. `jedikit-morning`: CLI `hermes cron edit` находит задание по ID или имени, повторный `create` создаёт дубль |
| `schedule` | `<MM> <HH> * * <дни>` — за ~10 минут до Daily open в выбранные дни, напр. `50 8 * * 1-5` |
| `skills` | `jedikit`, `jedikit-tasks`, `jedikit-calendar`, `jedikit-habits`. `jedikit` обязателен: cron подставляет значения `skills.config` только прикреплённых скиллов |
| `deliver` | Явно `telegram:<chat_id>:<thread_id>` — числовые ID чата и темы; не `origin` и не home channel |
| Toolsets cron-задания | Чтения серверов `singularity`, `google_calendar`, `habitify_read` и toolset `skills` — в `platform_toolsets.cron` Хоста или в `enabled_toolsets` задания, который важнее; без них запуск назовёт недостающее и покажет доступное |
| `prompt` | Текст ниже; плейсхолдеры `<…>` заменяет Потребитель |

```text
[расписание jedikit] Утреннее приглашение. Фоновый запуск: только читай и приглашай, ничего не записывай, вопросов не задавай.
Сегодняшнюю дату и день недели определи в поясе jedikit.timezone. Собери одно короткое сообщение:
1. Календарная часть утренней сводки jedikit-calendar.
2. Приглашение к Daily open (jedikit-tasks). План дня предложи после Daily open, в разговоре.
3. Если сегодня <день Weekly, напр. понедельник> — приглашение к Weekly.
4. Если сегодня <день Weekly> и число месяца от 1 до 7 — ещё к модулю Когда-нибудь, если поддеревья Когда-нибудь есть.
5. Число экспериментов jedikit-habits, у которых наступила дата обзора: только количество, без названий.
Соблюдай ограничения доставки скиллов-владельцев.
```

Создание через CLI (ID вымышлены):

```sh
hermes cron create '50 8 * * 1-5' "$(cat jedikit-morning.txt)" --name jedikit-morning \
  --skill jedikit --skill jedikit-tasks --skill jedikit-calendar --skill jedikit-habits \
  --deliver 'telegram:-1001234567890:17585'
```

**Ограничения:**

- **Timezone.** У задания нет своего пояса: cron считается по timezone Хоста (`HERMES_TIMEZONE`, затем `timezone` профиля). `jedikit.timezone` пояс cron не меняет — Потребитель задаёт их согласованно; после смены пояса Хоста перезапустите gateway.
- **Выбор по дате делает модель, а не cron.** Парсер Hermes v0.21.6 не принимает `3#1` («первая среда месяца»), а день месяца и день недели объединяет через OR: `0 9 1-7 * 1` срабатывает 1–7 числа и каждый понедельник. Поэтому день Weekly и первый Weekly месяца выбирает модель по тексту задания, а не календарный фильтр cron.
- **Только чтение.** Фоновый запуск только читает и приглашает: не пишет провайдерам и в `memory`, не создаёт Брони, не задаёт вопросов ([ADR 0003](docs/adr/0003-no-unattended-writes.md)). Приглашение не доказывает, что обзор состоялся; пропуски не отслеживаются.
- **Приватность.** Во внешнем уведомлении о привычках — только количества: без названий, заметок, Тяги и срывов.

## Разработка

Правила для разработчиков и агентов — [AGENTS.md](AGENTS.md). Для локальной проверки скиллов укажите в `skills.external_dirs` каталог `skills/` своего checkout; изменения подхватываются в новом экземпляре агента Hermes.

Проверки из корня, без аккаунтов провайдеров:

```sh
git diff --check "$(git hash-object -t tree /dev/null)" HEAD  # всё дерево HEAD, как в CI
git diff --check HEAD                                         # незакоммиченные правки
```

[CI](.github/workflows/check.yml) проверяет пробелы во всём дереве HEAD против пустого дерева; остальное — независимое ревью. Штатного валидатора Hermes для каталога в `skills.external_dirs` нет, поэтому валидность frontmatter, security scan и discovery скиллов автоматически не проверяются ([ADR 0017](docs/adr/0017-declarative-preferences.md)). Доступ к провайдерам, поведение модели и выполнение операций проверки не подтверждают.
