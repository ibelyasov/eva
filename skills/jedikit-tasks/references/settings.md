# Предпочтения, Режимы поддерева и status

## Предпочтения

Предпочтения задаёт Потребитель при подключении JediKit к Hermes. Хост добавляет их значения блоком к загруженному навигатору `jedikit`, который всегда в контексте:

```text
[Skill config (from ~/.hermes/config.yaml):
  jedikit.timezone = Europe/Moscow
  jedikit.tasks.workdays = ['mon', 'tue', 'wed', 'thu', 'fri']
]
```

Этому скиллу нужны два ключа:

| Ключ | Значение | Для чего |
| --- | --- | --- |
| `jedikit.timezone` | IANA timezone, например `Europe/Moscow` | «Сегодня», относительные даты, день обзора, Режимы поддерева |
| `jedikit.tasks.workdays` | Список дней из `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` | Режимы `рабочие дни` и `личные дни` |

- Значение — текст после `=` в строке ключа. Блок может содержать ключи других скиллов: читай только свои.
- `(not set)`, отсутствие строки или всего блока — предпочтение не задано. `skill_view(name="jedikit")` значения не подставляет: не загружай навигатор ради них.
- Не задано, а сценарию нужно: `jedikit.timezone` — для даты, `jedikit.tasks.workdays` — только когда в обзор попадают объекты с режимом `рабочие дни` или `личные дни`. Спроси нужное вместе с остальными блокирующими пробелами одним `clarify` без `choices`; ответ действует только в текущем разговоре. Назови ключ, который нужно задать у Потребителя. Ненужное сценарию не спрашивай.
- Скилл предпочтения не записывает: ни в `memory`, ни в файлы, ни в задачи, Теги или заметки.

### Изменение из чата

Фраза вроде «теперь рабочие дни со вторника по субботу» предпочтение не сохраняет. Назови ключ и новое значение для Потребителя, например `jedikit.tasks.workdays = ['tue', 'wed', 'thu', 'fri', 'sat']`, и скажи, что оно вступит в силу, когда Потребитель задаст его и перезапустит Хост. Если пользователь хочет, применяй новое значение в текущем разговоре.

## Режимы в памяти

`memory` этого скилла хранит только Режимы поддерева. Не храни предпочтения, пометки Папок, копии дерева или задач, Фокус-листы, остатки и состояние обзоров. Тип объекта определяй по [дереву](tree.md).

### Когда спрашивать режим

Режим нужен Daily open, Daily close, Weekly, месячному обзору Когда-нибудь и [осмотру Проекта](projects.md#осмотр). Если у объекта и всех его предков режима нет, спроси в этот момент, с рекомендацией по смыслу Области или Папки, например «Работа» → `рабочие дни`. Все такие объекты сценария — одним `clarify` без `choices` вместе с остальными пробелами; режимы перечисли по [дереву](tree.md#режимы-поддерева). Привязывай режим к ближайшей Области или Папке, а не к Проекту.

Выбор пользователя — полная явная команда: сохрани сразу и проверь по ответу `memory`. Без ответа режим не сохраняй и `всегда` не подставляй: покажи объект с пометкой «режим не выбран». Явная фраза вроде «пусть Личное будет всегда» тоже меняет режим: разреши ID объекта и запиши по [правилам записи](write-policy.md).

Если сохранённый ID исчез или перестал быть Областью или Папкой, уточни привязку; по похожему названию не заменяй.

### Где хранить

- Только инструмент `memory` с `target="memory"`: одна компактная запись, начинающаяся с `JediKit tasks:`, — ID Области или Папки → режим, например `JediKit tasks: <ID> рабочие дни; <ID> когда-нибудь`. Отдельного чтения нет: текущие записи видны в контексте памяти.
- Записи с этим префиксом нет — `action="add"`, `content`. Есть — `action="replace"`, `old_text` (уникальный фрагмент этой записи) и `content` с полной новой записью: replace заменяет запись целиком, поэтому перенеси в неё все сохраняемые режимы. Вторую запись не создавай, `target="user"` не используй.
- `done: true` — запись применена; это Read-back режима. `staged: true` с `pending_id` — запись ждёт одобрения: скажи «Сохранение ждёт подтверждения памяти: `/memory pending`» и не называй режим сохранённым. Отказ, например по лимиту, — `unapplied`; ответ без `done` и `staged` — `unverified`.
- Лимит около 2 200 символов на все записи памяти профиля: храни только ID и режимы, названия перечитывай у провайдера. При отказе по лимиту сообщи об этом; чужие записи не сокращай.
- Файлы скиллов JediKit (`SKILL.md`, `references/`, `tools.json`) только для чтения: не вызывай `skill_manage`, не создавай файлов настроек и не обходи `memory` другим способом, даже если подсказка Hermes советует хранить предпочтения в скилле.
- Если `memory` недоступен или сохранение не подтверждено, выбранный режим действует только в текущем разговоре; сохранение не обещай. Не заменяй память служебной задачей, проектом, Тегом или файлом.

## Status

1. Проверь инструменты сценария по видимому списку или через `tool_search`/`tool_describe`. Предпочтения прочитай из блока `jedikit`, Режимы поддерева — из записи `JediKit tasks:` в контексте памяти; без `memory` покажи режимы текущего разговора.
2. Не вызывай `get_my_context` и не читай задачи, проекты или данные аккаунта. Привязки ID покажи из памяти без проверки дерева.
3. Сообщи доступность возможностей запрошенного сценария и `memory`, значения предпочтений, режимы и пробелы. Для незаданного предпочтения назови ключ для Потребителя. Различай доступный, отсутствующий и неизвестный инструмент; наличие инструмента не доказывает рабочую авторизацию.
4. Приглашения к обзорам настраивает Потребитель; скилл их не видит и не показывает.
