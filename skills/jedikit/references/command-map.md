# Карта команд JediKit

Команда и естественная фраза равноправны. `status` и `help` есть у нескольких скиллов: называй их вместе с именем скилла. Отдельного setup в чате нет: предпочтения задаёт Потребитель, пометки объектов скилл-владелец спрашивает и сохраняет по ходу работы. Карта объясняет возможности; выполнение, инструменты и правила операций определяет загруженный скилл-владелец.

## `jedikit-tasks` — задачи и проекты, SingularityApp

| Команда или запрос | Результат |
| --- | --- |
| `capture`, «запиши», «сохрани, чтобы не забыть» | Обязательство или неясное — Inbox item с исходным текстом; идея, мысль, ссылка, файл — в Хранилище через `jedikit-notes`; затем строка, что и куда записано |
| `triage`, «разберём Inbox», «уточни задачу», смена даты | Тип Inbox item, чистовая формулировка, место в дереве; Срок или Плановая дата |
| `project`, «проверь проект», «следующий шаг», «закрой проект» | Результат проекта, стартуемый Следующий шаг, судьба открытых задач |
| Заметка о проекте в Хранилище | ID проекта для `jedikit-notes` и обратная ссылка в заметке проекта SingularityApp |
| Разделы, Теги, Чек-лист, явное изменение состояния задачи | Пользовательская структура или названное действие с задачей |
| `daily open`, «начнём день» | Вчерашние хвосты, Ресурс дня, Фокус-лист |
| `daily close`, «закроем день» | Остатки дня, затронутые проекты, Гвоздодёр: обязательства — во Inbox, мысли и идеи — в заметку дня через `jedikit-notes` |
| `weekly`, «еженедельный обзор» | Inbox, все проекты, Следующие шаги, структура |
| «Пересмотрим когда-нибудь» | Ежемесячный пересмотр поддеревьев Когда-нибудь |
| «Накопился Inbox» | Отдельная сессия Inbox debt |
| Утреннее приглашение по расписанию | Только чтение. Одно сообщение: календарная часть от `jedikit-calendar`, приглашение к Daily open, в день Weekly — к Weekly, в первый Weekly месяца — к модулю Когда-нибудь, число экспериментов `jedikit-habits` с наступившей датой обзора; задание заводит Потребитель |
| `status` | Предпочтения, Режимы поддерева и доступность инструментов, без чтения содержимого задач |
| `help` | Справка по задачам без обращения к аккаунту |

Встречу из Inbox с датой и временем создаёт как Событие `jedikit-calendar`; исходным Inbox item управляет `jedikit-tasks`. Идею из Inbox `jedikit-notes` переносит строкой с `#идея` в заметку дня, Справку — захватом: источник в `Источники/…` или адресная Заметка, Входящие хранилища — если адрес неясен. Исходный Inbox item отменяется только после подтверждённой записи: «перенеси и отмени» — сразу, «перенеси» — с предложением отменить. Kanban не поддерживается.

## `jedikit-habits` — поведение и Ритуалы, Habitify

| Команда или запрос | Результат |
| --- | --- |
| `design` | Одна гипотеза об одном поведении и План эксперимента |
| `log` | Отметка за дату или явно выбранная отмена |
| `urge` | Поддержка при Тяге по Плану эксперимента |
| `review` | Обзор эксперимента: оставить, изменить одну вещь, пауза или завершить |
| `adjust` | Изменение одной вещи в Плане эксперимента |
| `pause`, `archive` | Пауза или архив выбранной привычки |
| Явное удаление привычки, области или заметки | Запрошенное удаление по правилам владельца |
| `areas` | Группировка привычек по Областям Habitify |
| `rituals`, «собери ритуал» | Существующие привычки в Области Habitify, отмеченной как Ритуал |
| «Добавь звено», «убери звено» | Привычка входит в Ритуал или снимается с его Области без удаления; новое поведение начинается как эксперимент |
| «Сдвинь утренний ритуал на 7:00» | Новое время старта — напоминание первой привычки; связанный блок Распорядка меняет `jedikit-calendar` |
| «Статус ритуала» | Сколько привычек отмечено и какие пропущены; «выполнен» — только когда отмечены все |
| «Ритуал выполнен», «сделал утренний ритуал» | Отметки всех привычек Ритуала за дату |
| «Обзор ритуала» | Разбор Ритуала целиком |
| Заметка о привычке в Хранилище | ID привычки для `jedikit-notes` и обратная ссылка в описании привычки Habitify; План эксперимента, даты и Отметки остаются в Habitify |
| `status` | Предпочтения, Ритуалы и доступность инструментов |
| Еда, вес | Гипотеза о пищевом поведении без диеты |
| Порно, мастурбация | Отдельные эксперименты по каждому поведению |
| Сокращение, отказ, вещества | Учитываемое событие, критерии и безопасный вариант |
| Доказательства, сроки формирования, серия | Границы уверенности |
| `help` | Справка по привычкам без обращения к аккаунту |
| Time Off | Инструкция для приложения; команды `off` нет |

Порядок привычек Ритуала задаётся ручной сортировкой в приложении. Напоминания «после отметки A напомнить B» (`habitStacks`) — только по просьбе. Сон — одно действие, а не Ритуал.

## `jedikit-calendar` — личный календарь, Google Calendar

| Команда или запрос | Результат |
| --- | --- |
| «Что сегодня?», «покажи завтра», «покажи неделю» | События, Брони, Распорядок; у дня — Свободные окна и пересечения |
| «Когда у меня два часа?» | Вид дня со Свободными окнами; отдельного поиска нет |
| «Запиши встречу», «создай Событие», встреча из Inbox | Событие с датой, временем и длительностью или на весь день; возможен повтор |
| «Перенеси», «измени» | Изменение выбранного События; у серии — одно вхождение, это и следующие или вся серия |
| «Удали», «отмени Событие» | Удаление выбранного События или части серии |
| «Добавь сон в календарь», «добавь Распорядок» | Регулярный блок поведения с устойчивым временем и длительностью |
| «Напомни за час», «убери напоминания» | Напоминания записи по предпочтению её типа или просьбе |
| «Покрась в Заряд», «перекрась неделю по схеме» | Цвет записи по смыслу занятия; новые записи красятся по схеме сами |
| «Смени календарь записи», «поменяй границы дня» | Ключ предпочтения и новое значение для Потребителя; по желанию — только в этом разговоре |
| Календарная часть утренней сводки | Первое обязательное Событие, Свободные окна, пересечения, Распорядок; только чтение |
| `status` | Предпочтения календаря и доступность инструментов |
| `help` | Справка по календарю без обращения к аккаунту |

Читаются выбранные личные календари Google, запись идёт в один календарь записи. Намерение без договорённости и встреча без даты — задача для `jedikit-tasks`. Привычка с реальной договорённостью по времени может иметь Событие, сама привычка остаётся в Habitify. Вне скилла: рабочий Outlook, RSVP, приглашения участников, напоминания по умолчанию самого календаря (меняются в Google Calendar), подготовка к встрече, follow-up, задания расписания (их заводит Потребитель).

## `jedikit-planning` — План дня, без своего провайдера

| Команда или запрос | Результат |
| --- | --- |
| «Спланируй день», «влезают ли дела» | Лента дня, Свободные окна, осторожный вердикт вместимости, один набор выборочных Броней |
| «Забронируй 14–16 на отчёт» | Бронь под выбранную задачу |
| «Не влезает», «перепланируй день» | Перенос или снятие будущих Броней; при нехватке времени — предложение сдвинуть задачи |
| «Почему так», «на чём это основано» | Основания Плана дня и их пределы |
| `status` | Доступность нужных скиллов, инструментов и предпочтений, без чтения содержимого аккаунтов |
| `help` | Команды, границы Плана дня и следующий шаг, без обращения к аккаунтам |

Планируется только день. Распорядок и События не ужимаются ради задач. Прошедшая или пропущенная Бронь не закрывает задачу. Длительность берётся из `timeLength`, иначе грубая оценка с «≈» без записи в задачу.

## `jedikit-notes` — Хранилище Obsidian

| Команда или запрос | Результат |
| --- | --- |
| Вопрос по базе: «что я знаю о…», «сравни…» | Ответ по Хранилищу со ссылками на Заметки; в Хранилище сохраняется только по просьбе |
| «Сохрани ссылку», «сохрани в базу», присланная ссылка или файл | Захват: статья полным текстом в Источники, файл — в Источники как есть; неясное и неизвлечённое — во Входящие хранилища; без разбора |
| «Разбери статью», конспект лекции, материал сообщества | План сущностей; запись только после ответа владельца |
| «Запиши мысль», «запиши идею» | Строка в заметке дня; идея — одна строка с `#идея` |
| Дневник, запись о дне | Заметка дня за дату события в `jedikit.timezone`; время получения — отдельно |
| «Покажи идеи» | Страница всех идей: строки с `#идея` из Дневника и развиваемые идеи; отдельная Заметка идеи — только когда владелец решил её развивать |
| Lint, «проверь вики» | Отчёт о проблемах вики; исправления — по просьбе |
| Массовая правка по явной просьбе | Вся правка сразу целиком, с проверкой и записью в журнал Хранилища |
| Заметка о привычке или проекте | Знания, контекст и ID объекта провайдера; обратная ссылка у провайдера — через `jedikit-habits` или `jedikit-tasks` |
| «Держи X», «отпусти X» | Hold: агент не меняет Заметку X до «отпусти X» |
| `status` | Доступность Хранилища, инструментов и встроенных скиллов; предпочтения Хранилища |
| `help` | Справка по Хранилищу без чтения Заметок |

Хранилище хранит знания, значимое о дне и ссылки на объекты провайдеров; задачи, Отметки и События остаются у провайдеров. После каждой записи — проверка файла и Отчёт: сделано, не проверено, не сделано; автоматического отката нет, откат — история Git Хранилища. Фоновые запуски в Хранилище не пишут. Путь к Хранилищу и его синхронизацию настраивает Потребитель.

## `jedikit` — карта и предпочтения

«Что умеет JediKit», «куда это записать», «какой скилл выбрать», «покажи все команды», «что такое Бронь» — справка без чтения аккаунтов и операций. Глубокое уточнение намерения делает внешний `grill-me`, а не скилл JediKit.

| Команда или запрос | Результат |
| --- | --- |
| «Запиши …» обычными словами | Место по смыслу: обязательство, действие или неясное — Inbox `jedikit-tasks`; идея — строка с `#идея` в заметке дня, мысль или запись о дне — заметка дня, ссылка, файл, справка — захват `jedikit-notes`. Затем строка, что и куда; владелец поправит словами |
| «Какие у меня предпочтения?» | Значения из блока `[Skill config …]`; `(not set)` — не задано |
| «Теперь рабочие дни вт–сб», любое изменение предпочтения | Ключ и новое значение для Потребителя, без сохранения; по желанию — только в этом разговоре |
| «Напоминай о weekly», «пришли сводку в 8:00» | Расписание заводит Потребитель; назвать, что ему передать |
