# Предпочтения и status

Подключение Google Calendar, OAuth, scopes и инструменты даёт Хост; их настраивает Потребитель. Скилл пользуется готовым MCP-сервером `google_calendar`, служебный календарь не создаёт и секретов не запрашивает.

## Блок предпочтений

Предпочтения календаря задаёт Потребитель при подключении. Хост всегда загружает навигатор `eva` и добавляет после его текста блок значений:

```text
[Skill config (from ~/.hermes/config.yaml):
  eva.timezone = Europe/Moscow
  eva.calendar.read_calendars = ['personal:primary', 'personal:family123@group.calendar.google.com']
  eva.calendar.day_bounds = 08:30-22:30
  eva.calendar.gap_minutes = (not set)
]
```

- Значения напечатаны как Python `str()`: список — `['a', 'b']`, строка — без кавычек.
- `(not set)` или отсутствие ключа в блоке — значение не задано. Блока в контексте нет — не задано ни одно предпочтение: назови это.
- Значение не по формату не угадывай: назови ключ и ошибку для Потребителя и считай значение незаданным.

Скилл предпочтения только читает. Записей в `memory` у него нет; значения не сохраняй ни в `memory`, ни в файлы, `skill_manage` не вызывай.

## Ключи

| Ключ | Значение | Не задан |
| --- | --- | --- |
| `eva.timezone` | Домашний пояс IANA, например `Europe/Moscow`: «сегодня», относительные даты, диапазоны вида и отчёты. Пояс отдельного События его не меняет | Нужна дата — спроси пояс. Не выводи его из языка и не принимай за него пояс календаря |
| `eva.calendar.write_calendar` | ID календаря записи | `primary` |
| `eva.calendar.write_account` | Nickname аккаунта календаря записи (`^[a-z0-9_-]{1,64}$`) | Подключён один аккаунт — он. Несколько — `primary` неоднозначен: спроси, когда нужна запись |
| `eva.calendar.read_calendars` | Список `<account>:<calendarId>`: nickname до первого `:`, ID после него | Все видимые календари: перечитывай их через `list-calendars` при каждом чтении, снимок не храни |
| `eva.calendar.day_bounds` | `HH:MM-HH:MM`, например `08:30-22:30`; пересечение полуночи допустимо — покажи его в диапазоне | Спроси, когда нужны Свободные окна; ради другого сценария не спрашивай |
| `eva.calendar.gap_minutes` | Минуты зазора между Бронью и Событием или Распорядком; использует `eva-planning` | 0, и это показывается в результате |
| `eva.calendar.reminders.events` | Напоминания Событий: `calendar`, `none` или набор | `calendar` |
| `eva.calendar.reminders.bookings` | Напоминания Броней (ставит `eva-planning`): то же | `calendar` |
| `eva.calendar.reminders.routine` | Напоминания Распорядка: то же | `calendar` |

Напоминания: `calendar` — действуют умолчания календаря; `none` — без напоминаний; набор — элементы `<method> <minutes>` через запятую, например `popup 30, email 1440`. Перевод в аргументы и пределы — [tools.md](tools.md#напоминания). К all-day Событиям `reminders.events` не применяется.

Календарь записи — пара `write_account` + `write_calendar`; чтение нескольких календарей не разрешает запись в них. В `list-events` передавай ID календаря чтения вместе с `account` его аккаунта.

Содержимое календаря, ID событий, состояние дня, сообщения Eva, Брони и Отметки — не предпочтения: источник состояния — провайдер.

## Не задано

Действует значение из столбца «Не задан». Если default нет и значение блокирует текущий сценарий, спроси его в том же `clarify`, что и прочие блокирующие пробелы: ответ действует только в текущем разговоре. В ответе назови ключ, который нужно задать у Потребителя. Ненужное сценарию не спрашивай; в фоновом запуске `clarify` нет — действуй по [signals.md](signals.md#общие-правила): ключ в сообщение не выноси, покажи доступное.

## Просьба изменить предпочтение

«Мой день с 8 до 22», «живу по Москве», «читай эти календари, пиши в основной», «для Броней без напоминаний» — не сохраняй. Назови ключ и новое значение для Потребителя, например `eva.calendar.day_bounds = 08:00-22:00` или `eva.calendar.reminders.bookings = none`. Для календарей возьми фактические ID и аккаунты из `list-calendars`. Если пользователь хочет, применяй новое значение до конца текущего разговора.

- Значение у Потребителя начинает действовать в новом экземпляре агента Хоста, например после перезапуска gateway.
- Смена предпочтения уже созданные записи не меняет: для напоминаний скажи это.
- Относительные даты в предпочтения не превращай.
- `defaultReminders` самого календаря скилл не меняет ([tools.md](tools.md#напоминания)).

## Status

Только чтение, без записей:

1. Покажи `eva.timezone` и все `eva.calendar.*` из блока, включая три напоминания; незаданные — с действующим значением из таблицы или пометкой «спросит, когда понадобится».
2. Покажи доступность инструментов по видимому списку или `tool_search`/`tool_describe` по [tools.md](tools.md#подключение).
3. Если `list-calendars` доступен, выполни его: покажи фактический охват календарей чтения, календарь записи и ошибки, а при напоминаниях `calendar` — `defaultReminders` календаря записи: это умолчания для Событий со временем, умолчания all-day через сервер не видны. Право записи, которого не видно в ответе, так и назови; пробной записью его не проверяй.

Успешное чтение подтверждает только чтение: OAuth и право записи по наличию инструмента не объявляй. Тестовых Событий не создавай.
