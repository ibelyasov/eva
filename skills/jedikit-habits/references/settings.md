# Предпочтения, память, status и фоновый запуск

Записи в Habitify и `memory` — по [write-policy.md](write-policy.md).

## Предпочтения

Предпочтения задаёт Потребитель — сторона, которая подключает JediKit к Hermes, — в конфигурации Хоста. Скилл их только читает и никуда не записывает: ни в `memory`, ни в файлы.

Значения Hermes добавляет к загруженному навигатору `jedikit` блоком такого вида:

```text
[Skill config (from ~/.hermes/config.yaml):
  jedikit.timezone = Europe/Moscow
  jedikit.habits.names = (not set)
]
```

Этот скилл читает два ключа:

| Ключ | Значение | Если не задан |
| --- | --- | --- |
| `jedikit.timezone` | IANA timezone, например `Europe/Moscow`: «сегодня», относительные даты, даты Отметок, статистики и обзора | Спроси, когда сценарию нужна дата |
| `jedikit.habits.names` | `exact` — точные названия; `neutral` — нейтральные для чувствительных тем | Спроси при создании чувствительной привычки ([Названия](#названия)) |

- Не задано — значение `(not set)` или ключа нет в блоке. Нет блока в контексте — все предпочтения не заданы; файлы навигатора и конфигурацию Хоста ради значений не читай. Значение вне формата считай незаданным и скажи об этом.
- Не задано, а сценарию нужно — спроси для текущего разговора: timezone — в общем `clarify` с остальными блокирующими пробелами, стиль названий — по [Названия](#названия). Назови ключ, который Потребителю стоит задать, чтобы вопрос не повторялся. Ненужное сценарию не спрашивай.
- Просьба изменить предпочтение из чата («теперь я в Тбилиси») — не сохраняй. Назови ключ и новое значение для Потребителя (`jedikit.timezone = Asia/Tbilisi`) и по желанию пользователя применяй его только в текущем разговоре. Изменение у Потребителя действует в новом экземпляре агента Хоста.

## Названия

Не пытайся отличить владельца от участника публичного onboarding. Для нового названия используй явно заданное имя или `jedikit.habits.names`. Если привычка чувствительная, а имя и стиль не заданы, спроси о точном или нейтральном имени вместе с остальными блокирующими пробелами; выбор действует в текущем разговоре, ключ назови для Потребителя. Объясни, что названия видны в Habitify и его напоминаниях. Чувствительное название по собственной догадке не создавай; в сексуальной теме — [sexual-behavior.md](sexual-behavior.md#возраст).

## Открытый запрос

Отдельной настройки нет. «Давай настроим привычки», «с чего начать» — обычная работа без анкеты:

1. Проверь инструменты серверов `habitify_read` и `habitify` для сценария, включая Read-back, по [tools.md](tools.md#серверы-и-discovery). Покажи существующие привычки ([поиск](tools.md#поиск-привычки-по-названию)).
2. Если привычка и действие уже названы, найди её и выполни запрос без повторного выбора. Иначе предложи один подходящий ход одной строкой и выполни по «Да»; набор изменений — один Preview. Новую привычку веди по [experiments.md](experiments.md), выбранной — прочитай детали и заметку плана по [experiments.md](experiments.md#заметка-плана).

Потребность в группировке — [areas.md](areas.md#когда-предложить). Запрос Ритуала — [rituals.md](rituals.md); вопросы о Ритуалах, предпочтениях или расписании без запроса не задавай. Приглашения по расписанию настраивает Потребитель: на просьбу о них назови, какое приглашение нужно, и не создавай заданий.

## Память

`memory` хранит только Ритуалы: `areaId` Областей, выбранных пользователем как Ритуалы, и для каждой — `habitId` первой привычки, если пользователь её назвал. Запись делается по ходу работы с Ритуалом ([rituals.md](rituals.md#ритуал-в-памяти)).

Не храни: предпочтения, даты и ритм обзоров, ID экспериментов и остальных привычек, состав и порядок Ритуала, План эксперимента, состояния «активный / Поддержание / пауза», Отметки, Тягу, вес, причины срыва, секреты.

### Запись в memory

- Только инструмент `memory` с `target="memory"`: одна компактная запись этого скилла, начинающаяся с `JediKit habits:`. Отдельного чтения нет: текущие записи видны в контексте памяти.
- Записи с этим префиксом нет — `action="add"`, `content`. Есть — `action="replace"`, `old_text` (уникальный фрагмент этой записи) и `content` с полной новой записью: replace заменяет запись целиком, поэтому перенеси в неё все сохраняемые Ритуалы. Вторую запись не создавай, `target="user"` не используй.
- `done: true` — запись применена; это Read-back памяти. `staged: true` с `pending_id` — запись ждёт одобрения: скажи «Сохранение ждёт подтверждения памяти: `/memory pending`» и не называй Ритуал сохранённым. Отказ, например по лимиту, — `unapplied`; ответ без `done` и `staged` — `unverified`.
- Лимит около 2 200 символов на все записи памяти профиля: храни только ID, остальное перечитывай у провайдера. При отказе по лимиту сообщи об этом; чужие записи не сокращай.
- Файлы скиллов JediKit (`SKILL.md`, `references/`, `tools.json`) только для чтения: не вызывай `skill_manage`, не создавай файлов настроек и не обходи `memory` другим способом, даже если подсказка Hermes советует хранить что-то в скилле.
- `memory` недоступен — один раз за сессию сообщи ограничение; выбранный Ритуал действует только в текущем разговоре, сохранение не обещай.

## Status

- `status` без объекта — значения `jedikit.timezone` и `jedikit.habits.names` из блока (незаданное — «не задано» с ключом для Потребителя), Ритуалы из памяти, доступность инструментов `habitify_read` и `habitify` для основных сценариев по [tools.md](tools.md#серверы-и-discovery) и активные привычки.
- Эксперимент: найди привычку, прочитай детали и адресную статистику за запрошенный период (по умолчанию — текущая дата по [tools.md](tools.md#даты-и-единицы)). Покажи наблюдаемое поведение, доступные Отметки, дату обзора из доступного плана и ограничения данных. План нужен для разбора и даты обзора; простое чтение Отметок выбором заметки не задерживай.
- «Какие привычки сегодня?» или конкретный день — [Обзор дня](tools.md#обзор-дня), без записи Отметок.
- Ритуал — [rituals.md](rituals.md#статус).

Отделяй слова пользователя от прочитанного в Habitify. Соблюдение плана или факт обзора из пропущенных данных не выводи. Status только читает.

## Фоновый запуск

Задания расписания создаёт и сопровождает Потребитель; скилл их не создаёт и не меняет. Запуск с маркером `[расписание jedikit]` только читает ([write-policy.md](write-policy.md#фоновый-запуск)), `clarify` в нём нет.

- Обзоры: прочитай активные привычки и их Планы эксперимента и сосчитай эксперименты, у которых дата обзора из плана наступила в `jedikit.timezone`. Заметку плана выбирай по [experiments.md](experiments.md#заметка-плана) без вопроса: если план однозначно не установлен или в нём нет даты, просрочку не утверждай и эксперимент не считай. Без `jedikit.timezone` наступление даты не утверждай и назови ключ.
- Нужно чтение `habitify_read` в инструментах фонового запуска. Если их нет, назови недостающее и покажи только доступное, без обхода.
- Пропущенный обзор не отслеживай и ledger в памяти не создавай.

Во внешнем уведомлении сообщай только количества, например «Есть 1 эксперимент для обзора». Названия привычек, заметки, Тягу, срывы и другие чувствительные подробности не включай.
