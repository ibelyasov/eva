# Предпочтения, Режимы поддерева и status

## Предпочтения

Предпочтения задаёт Потребитель при подключении Eva к Hermes. Хост добавляет их значения блоком к загруженному навигатору `eva`, который всегда в контексте:

```text
[Skill config (from ~/.hermes/config.yaml):
  eva.timezone = Europe/Moscow
  eva.tasks.workdays = ['mon', 'tue', 'wed', 'thu', 'fri']
]
```

Этому скиллу нужны два ключа:

| Ключ | Значение | Для чего |
| --- | --- | --- |
| `eva.timezone` | IANA timezone, например `Europe/Moscow` | «Сегодня», относительные даты, день обзора, Режимы поддерева |
| `eva.tasks.workdays` | Список дней из `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` | Режимы `рабочие дни` и `личные дни` |

- Значение — текст после `=` в строке ключа. Блок может содержать ключи других скиллов: читай только свои.
- `(not set)`, отсутствие строки или всего блока — предпочтение не задано. `skill_view(name="eva")` значения не подставляет: не загружай навигатор ради них.
- Не задано, а сценарию нужно: `eva.timezone` — для даты, `eva.tasks.workdays` — только когда в обзор попадают объекты с режимом `рабочие дни` или `личные дни`. Спроси нужное вместе с остальными блокирующими пробелами одним `clarify` без `choices`; ответ действует только в текущем разговоре. Назови ключ, который нужно задать у Потребителя. Ненужное сценарию не спрашивай.
- Скилл предпочтения не записывает: ни в Журнал Eva, ни в `memory`, ни в файлы, ни в задачи, Теги или заметки.

### Изменение из чата

Фраза вроде «теперь рабочие дни со вторника по субботу» предпочтение не сохраняет. Назови ключ и новое значение для Потребителя, например `eva.tasks.workdays = ['tue', 'wed', 'thu', 'fri', 'sat']`, и скажи, что оно вступит в силу, когда Потребитель задаст его и перезапустит Хост. Если пользователь хочет, применяй новое значение в текущем разговоре.

## Режимы в Журнале

Режимы поддерева — Пометки объектов этого скилла — хранятся в `Eva/Пометки.md` Журнала Eva. Путь к Журналу и форму строк задаёт `skill_view(name="eva", file_path="references/notebook.md")`. Не храни там предпочтения, пометки Папок, копии дерева или задач, Фокус-листы и остатки; даты обзоров — в `Eva/Практики.md` по [signals.md](signals.md#отметки-в-практиках). Тип объекта определяй по [дереву](tree.md). `memory` Hermes не используй.

### Когда спрашивать режим

Режим нужен Daily open, Daily close, Weekly, месячному обзору Когда-нибудь и [осмотру Проекта](projects.md#осмотр). Если у объекта и всех его предков режима нет, спроси в этот момент, с рекомендацией по смыслу Области или Папки, например «Работа» → `рабочие дни`. Все такие объекты сценария — одним `clarify` без `choices` вместе с остальными пробелами; режимы перечисли по [дереву](tree.md#режимы-поддерева). Привязывай режим к ближайшей Области или Папке, а не к Проекту. В фоновом запуске не спрашивай: объект без режима ждёт разговора.

Выбор пользователя — полная явная команда: сохрани сразу и проверь по [правилам записи](write-policy.md#журнал-eva). Без ответа режим не сохраняй и `всегда` не подставляй: покажи объект с пометкой «режим не выбран». Явная фраза вроде «пусть Личное будет всегда» тоже меняет режим: разреши ID объекта и запиши.

Если сохранённый ID исчез или перестал быть Областью или Папкой, уточни привязку; по похожему названию не заменяй.

### Где хранить

- Чтение: `read_file` файла `<корень>/Eva/Пометки.md` один раз за разговор или запуск, когда сценарию нужны режимы. Корень — по «Корню Хранилища» в `notebook.md`: в разговоре абсолютный путь из переменных окружения, в фоне — `workdir` задания и относительный путь `Eva/Пометки.md`. Нет файла (это подтвердил `search_files`) или строк этого скилла — режимов пока нет; другая ошибка чтения — режимы неизвестны, в Журнал не пиши.
- Запись: перечитай файл, измени или добавь только строки Режимов поддерева по форме `notebook.md` — ID Области или Папки и режим; строки `eva-habits` и правки владельца сохрани. Правка владельца в файле важнее записи Eva.
- Проверка — `read_file` после записи: строка с ID и режимом на месте — `applied`; не удалось прочитать — `unverified`; запись не выполнена — `unapplied`.
- Храни ID и режимы, названия перечитывай у провайдера.
- Файлы скиллов Eva (`SKILL.md`, `references/`, `tools.json`) только для чтения: не вызывай `skill_manage` и не создавай файлов настроек рядом со скиллом, даже если подсказка Hermes советует хранить предпочтения в скилле.
- Нет Хранилища или toolset `file` — выбранный режим действует только в текущем разговоре: назови недостающее и сохранение не обещай. Не заменяй Журнал служебной задачей, проектом, Тегом или `memory`.
