# Weekly

1. Прочитай Inbox через `task_list_inbox` и разбирай Inbox items по одному по [Triage](inbox.md#triage). Большой остаток вынеси в отдельные сессии [Inbox debt](inbox.md#inbox-debt); неразобранные записи обработанными не объявляй.
2. Прочитай всё доступное дерево по [tools.md](tools.md#дерево-в-разговоре) и пройди все Области и Проекты вместе с Разделами и одиночными Задачами Областей, а не только затронутые Проекты. Режим, которого нет ни у Проекта, ни у его Области, спроси по [settings.md](settings.md#когда-спрашивать-режим).
3. Для каждого активного Проекта проведи [осмотр](projects.md#осмотр).
4. Перечисли поддеревья Когда-нибудь. В выбор недели их не включай; все они проверяются на [месячном обзоре](someday.md).
5. Проверь актуальность открытых Задач и известных Сроков, включая просроченные через `task_list_overdue`. Обязательной недельной квоты нет.
6. Прочитанные открытые Задачи, которые не проходят проверку «как для обезьянки» по [tasks.md](tasks.md#формулировка), собери с вариантом переформулировки каждой.
7. Подготовь предложения по Разделам и Тегам по [structure.md](structure.md), по эмодзи и цвету — по [projects.md](projects.md#эмодзи-и-цвет-существующих-проектов), по вложенным проектам — по [дереву](tree.md#вложенные-проекты).
8. Изменения по итогам обхода, включая переформулировки, собери в один Preview; Triage остаётся разбором по одному, выбранный набор веди без вопроса о продолжении. Уже выполненное не повторяй.
9. Сообщи охват, оставшиеся решения и ограничения.

Замеченное по ходу, но не входящее в обзор, обзор не прерывает — по [signals.md](signals.md#во-время-практики). В конце отметь Weekly по [signals.md](signals.md#отметки-в-практиках); прерванный обзор полным не называй — перечисли непросмотренное.
