# Дерево и Режимы поддерева

Тип объекта и режим определяй по актуальному дереву из `project_list`/`project_get`; пометок, служебных Тегов и строк Журнала для типа нет. Режимы хранятся в `Eva/Пометки.md` Журнала Eva по [settings.md](settings.md#режимы-в-журнале).

## Типы

| Тип | Как определить | Что требует |
| --- | --- | --- |
| Область | Проект верхнего уровня, даже без дочерних: `Работа`, `Личное` или выбранный пользователем | Ни результата, ни Следующего шага |
| Папка | Проект ниже Области, у которого есть дочерние проекты. Крупное дело, разбитое на подпроекты, тоже Папка; его шаги живут в подпроектах | Ни результата, ни Следующего шага; может держать одиночные задачи |
| Проект | Проект ниже Области без дочерних проектов | Результат и стартуемый Следующий шаг, кроме режима `когда-нибудь` |

Показывай дерево по фактическим связям; одинаковые названия различай по пути и ID. Одиночные задачи живут прямо в Области или Папке; проект `Общее` не создавай.

## Области и Папки в работе

Нужны чтение проектов с ID, названием и родителем, а для новых объектов — `project_create` с родителем. Отличай пустое дерево от недоступного чтения.

1. Существующее устройство не переименовывай, не перемещай и не мигрируй. Подходящая структура не требует переустройства; на «настрой дерево» покажи дерево, Режимы поддерева и пробелы.
2. Если для места в Triage, Проекта или запроса о дереве нет подходящих Областей, предложи `Работа` и `Личное` или названия пользователя. В том же предложении назови режим каждой Области с рекомендацией, например «Работа» → `рабочие дни`. Рекомендация — не выбор: режим без согласия пользователя не сохраняй.
3. Режим привязывай только к Области или Папке по актуальному дереву. Для нового объекта укажи имя, родителя и место будущего ID. Новая Папка требует хотя бы одного реального дочернего проекта в той же Группе операций; иначе отложи привязку до его появления. Фиктивные дочерние проекты и пометки ради типа не создавай.
4. Preview набора, собранного агентом, показывает связи, режимы, порядок создания и привязку будущих ID.
5. Создай разрешённые объекты, получи их ID и перечитай дерево. Режим сохраняй по [settings.md](settings.md#где-хранить), только когда Read-back подтвердил Область или Папку с дочерним проектом.
6. Покажи дерево, режимы и оставшиеся пробелы; незавершённые части назови явно.

## Режимы поддерева

Режим назначается Области или Папке и наследуется вниз от ближайшего явно настроенного предка. На каждый проект его не копируй. Если режима нет ни у одного предка, спроси его по [settings.md](settings.md#когда-спрашивать-режим); `всегда` по умолчанию не назначай.

| Режим | Daily open и Daily close |
| --- | --- |
| `рабочие дни` | Только в дни `eva.tasks.workdays` по `eva.timezone` ([settings.md](settings.md#предпочтения)) |
| `личные дни` | В остальные дни недели; без календаря праздников и догадок о выходных |
| `всегда` | Независимо от дня недели |
| `когда-нибудь` | Не включается; Следующий шаг не нужен; пересмотр раз в месяц по [someday.md](someday.md) |

Режим не меняет даты, состояние задач и дерево в SingularityApp. Не выводи его из возраста или количества задач.
