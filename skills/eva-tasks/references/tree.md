# Дерево и Режимы поддерева

Тип объекта и режим определяй по актуальному дереву из `project_list`/`project_get`; пометок, служебных Тегов и строк Журнала для типа нет. Режимы хранятся в `Eva/Пометки.md` Журнала Eva по [settings.md](settings.md#режимы-в-журнале).

## Типы

| Тип | Как определить | Что требует |
| --- | --- | --- |
| Область | Проект верхнего уровня, даже без дочерних: `Работа`, `Личное` или выбранный пользователем | Ни результата, ни Следующего шага; цвет, общий для её Проектов |
| Проект | Проект прямо в Области | Стартуемый Следующий шаг, кроме режима `когда-нибудь`; эмодзи и цвет своей Области |

Дерево — два уровня проектов: Область → Проект. Всё, что ниже Проекта, — [Раздел](structure.md#разделы), а не проект. Одиночные задачи живут прямо в Области или в её Разделах; проект `Общее` не создавай. Показывай дерево по фактическим связям; одинаковые названия различай по пути и ID.

## Вложенные проекты

Проект глубже второго уровня до превращения считается Разделом своего Проекта второго уровня: режим и Следующий шаг осмотр берёт у этого Проекта, отдельного Проекта без шага нет. По просьбе владельца или на Weekly предложи одним Preview превратить его в Раздел: создать Раздел через `task_group_create` в Проекте второго уровня, перенести Задачи через `task_move` с сохранением ID, затем архивировать пустой вложенный проект через `project_archive` по [projects.md](projects.md#закрытие-или-отказ).

## Цвет Области

Цвет — один на Область. Новой Области его выбирает агент при создании, Проект получает `color` своей Области; это часть команды создания, отдельного согласия не нужно. `color` — hex `#RRGGBB`, например `#4A90E2`. Эмодзи Проекта — по [projects.md](projects.md#создание-и-изменение).

## Области в работе

Нужны чтение проектов с ID, названием и родителем, а для новых объектов — `project_create` с родителем. Отличай пустое дерево от недоступного чтения.

1. Существующее устройство не переименовывай, не перемещай и не мигрируй. Подходящая структура не требует переустройства; на «настрой дерево» покажи дерево, Режимы поддерева и пробелы.
2. Если для места Задачи, Проекта или запроса о дереве нет подходящих Областей, предложи `Работа` и `Личное` или названия пользователя. В том же предложении назови режим каждой Области с рекомендацией, например «Работа» → `рабочие дни`. Рекомендация — не выбор: режим без согласия пользователя не сохраняй.
3. Режим привязывай к Области по актуальному дереву, `когда-нибудь` — ещё к отдельному Проекту. Для нового объекта укажи имя, родителя и место будущего ID.
4. Preview набора, собранного агентом, показывает связи, режимы, порядок создания и привязку будущих ID.
5. Создай разрешённые объекты, получи их ID и перечитай дерево. Режим сохраняй по [settings.md](settings.md#где-хранить), только когда Read-back подтвердил объект.
6. Покажи дерево, режимы и оставшиеся пробелы; незавершённые части назови явно.

## Режимы поддерева

Активный режим назначается Области и действует на все её Проекты; на каждый Проект его не копируй. `когда-нибудь` назначается Области или отдельному Проекту; у Проекта он важнее режима Области. Если режима нет ни у Проекта, ни у его Области, спроси его по [settings.md](settings.md#когда-спрашивать-режим); `всегда` по умолчанию не назначай.

| Режим | Daily open и Daily close |
| --- | --- |
| `рабочие дни` | Только в дни `eva.tasks.workdays` по `eva.timezone` ([settings.md](settings.md#предпочтения)) |
| `личные дни` | В остальные дни недели; без календаря праздников и догадок о выходных |
| `всегда` | Независимо от дня недели |
| `когда-нибудь` | Не включается; Следующий шаг не нужен; пересмотр раз в месяц по [someday.md](someday.md) |

Режим не меняет даты, состояние задач и дерево в SingularityApp. Не выводи его из возраста или количества задач.
