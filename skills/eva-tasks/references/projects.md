# Проекты

Тип объекта и наследуемый режим — по [дереву](tree.md). Формулировку и состояние Задач — по [tasks.md](tasks.md).

## Осмотр

1. Прочитай объект через `project_get`, дерево — по [tools.md](tools.md#дерево-в-разговоре), открытые Задачи через `task_list`.
2. Покажи открытые Задачи, препятствия и Следующий шаг, а результат — если он записан в заметке Проекта. Неизвестный результат осмотр не блокирует: о нём не спрашивай и слово «результат» в вопросах владельцу не используй. Число выполненных Задач не доказывает, что дело сделано.
3. Если режима нет ни у Проекта, ни у его Области, спроси его по [settings.md](settings.md#когда-спрашивать-режим). Активному Проекту нужен стартуемый Следующий шаг. Используй выбранный; если его нет, предложи один, два — если они независимы и параллельны. Полный будущий план не придумывай.
4. Существующую Задачу переиспользуй через `task_update` или `task_move`, новую создавай через `task_create`. Копии Задач ради организации не создавай.

## Создание и изменение

1. «Добавь проект …» — полная явная команда: создай Проект сразу через `project_create`, без вопросов о результате и первом шаге.
   - Название — вычищенное, как формулировка задачи по [tasks.md](tasks.md#формулировка): своими словами, без «Re:», «Fwd:» и мусора исходного текста.
   - Родитель — названная владельцем Область, иначе Область по смыслу; Проект создаётся только в Области ([дерево](tree.md#типы)). Родителем назван Проект («добавь проект X в проект Y», «подпроект в Y») — это Раздел X в Проекте Y по [structure.md](structure.md#разделы). Областей нет — по [дереву](tree.md#области-в-работе).
   - `emoji` — один эмодзи по смыслу названия, `color` — цвет Области по [дереву](tree.md#цвет-области); у Области нет цвета — Проект создай без `color`, а Область и её Проекты включи в Preview по [эмодзи и цвету](#эмодзи-и-цвет-существующих-проектов). Их выбирает агент; отдельного согласия не нужно.
2. Первый шаг, названный владельцем, — Задача Проекта в той же Группе операций. Результат, названный владельцем, — в заметку Проекта; сам его не формулируй. Проект без шага заметит [осмотр](#осмотр) на Weekly.
3. После создания — одна строка: путь, название с эмодзи и ID. Владелец поправит словами.
4. Изменение — `project_update`; поля родителя и заметки передавай лишь при их изменении. Новый родитель Проекта — только Область. Заметку меняй, сохраняя прежний текст.
5. Preview набора, собранного агентом, показывает родителя, название, эмодзи, цвет и точные изменения Задач.
6. Создай или измени Проект, затем выполни операции над Задачами с полученными ID.

## Эмодзи и цвет существующих Проектов

По просьбе владельца или на Weekly собери Проекты без `emoji` или `color` и Области без цвета в один Preview: по строке на объект — путь, предлагаемые эмодзи и цвет по [дереву](tree.md#цвет-области). После подтверждения — `project_update` с `id` и только `emoji`/`color`, последовательно со стопом на первой ошибке и Read-back каждого. Таких объектов нет — не предлагай.

## Закрытие или отказ

1. Прочитай Проект, его открытые Задачи и Разделы. Для Области нужны решения по всем её Проектам.
2. Завершение — по слову владельца; результат для него не требуй. При отказе причину не требуй; записывай её в заметку через `project_update`, только если пользователь выбрал её сохранить, сохраняя прежний текст.
3. По каждой открытой Задаче нужно решение: завершить выполненную, перенести нужную, отменить ненужную или явно оставить открытой в архиве. Используй выбранные `task_complete`, `task_cancel`, `task_move`, `task_update`. Список молча не отменяй.
4. Установи охват `project_archive`: потомки, открытые и повторяющиеся Задачи. Если последствия неизвестны, предложи ручную операцию в приложении.
5. Preview набора, собранного агентом, показывает изменение заметки, судьбу каждой Задачи и последствия архива.
6. Выполни изменения заметки и Задач, `project_archive` — последним.

Возвращение из архива — `project_unarchive` с установленным охватом. Восстановление прежних состояний и повторений не обещай; их изменения, если пользователь их явно не назвал, предлагай отдельно.

## Заметка о проекте в Хранилище

Заметку о проекте в Хранилище Obsidian — материалы, контекст, решения, ID и ссылку — ведёт `eva-notes`. Результат, состояние, Задачи и Следующий шаг остаются в SingularityApp и в Хранилище не дублируются.

- ID проекта для `eva-notes` только читай через `project_get`/`project_list`. Не найден или кандидатов несколько — так и скажи; проект по отсутствию не создавай. Ссылку на проект передавай, только если её вернул провайдер; URL сам не собирай.
- Обратная ссылка: когда `eva-notes` создал Заметку о проекте как часть просьбы пользователя, допиши в заметку проекта SingularityApp строку `Obsidian: <путь без .md>` и, если задан `eva.notes.vault_name`, URI `obsidian://open?vault=<имя>&file=<путь без .md>` с percent-encoding. Путь и имя хранилища даёт `eva-notes`.
  1. Прочитай проект через `project_get` и полный текущий текст заметки. Текст не прочитан — не пиши: `unapplied` с причиной. Строка с тем же путём уже есть — записи не нужно.
  2. `project_update` с `id` и `note` = прежний текст без изменений + новые строки в конце; другие поля не передавай.
  3. Read-back `project_get`: прежний текст сохранён, новые строки на месте.
  4. Эта запись — часть просьбы пользователя о Заметке: отдельное подтверждение не нужно. Результат `applied`/`unverified`/`unapplied` — отдельной строкой в Отчёте `eva-notes`.
- Для существующих проектов обратные ссылки массово не проставляй.
