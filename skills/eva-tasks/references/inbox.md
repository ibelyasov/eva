# Inbox: Задача по просьбе, Capture, Triage, Inbox debt

## Задача по просьбе

«Добавь задачу …», «поставь задачу …», «запиши задачу …» — просьба с явным словом «задача» — или присланный материал — письмо, сообщение, ссылка — с такой просьбой — полная явная команда: Capture и разбор в одном ходе, повторного Triage задача не ждёт. Голое «запиши …» без слова «задача» и неясное — по [Capture](#capture).

1. Сформулируй задачу начисто по [tasks.md](tasks.md#формулировка). Очевидный признак готовности формулируй сам: «позвонить Пете» → «звонок состоялся». Один `clarify` без `choices` со всеми пробелами задай до создания, только если неясно, что именно сделать, или признак готовности нельзя вывести из текста. Иначе создавай без вопросов. Даты, приоритет, «зачем» и результат проекта не спрашивай.
2. Собери заметку по [tasks.md](tasks.md#заметка).
3. Выбери [место по смыслу](#место-по-смыслу).
4. Создай задачу одним `task_create` в выбранном месте с формулировкой и заметкой. Даты, приоритет и длительность — только названные владельцем. Выполни Read-back.
5. Одна строка: формулировка, путь места и ID. Владелец поправит словами; поправка — полная явная команда.

Несколько названных задач — Группа операций: каждую веди этими шагами, последовательно со стопом на первой ошибке; блокирующие пробелы всех задач — в одном `clarify`.

### Место по смыслу

Дерево Областей, Проектов и Разделов бери из разговора по [tools.md](tools.md#дерево-в-разговоре). Явно названное владельцем место важнее выбора.

- Место выбирай по смыслу задачи и названиям Областей, Проектов и Разделов. Место — самое узкое подходящее: Раздел, затем Проект, затем Область; Область — место, только когда задаче не подходит ни один её Проект или Раздел. Подходит одно место — клади туда и назови путь.
- Несколько мест — это равноправные кандидаты разных веток, например два Проекта или две Области, а не Проект и его Область. Подходят несколько или ни одного — клади во Inbox: его разберёт Weekly или [Triage](#triage). Ради места не спрашивай и новый Проект или Раздел не создавай.
- Открытые задачи ради выбора места заранее не читай.

## Capture

«Запиши …» обычными словами, без префиксов, — полная явная команда: место выбирает агент по смыслу записи и пишет сразу, без предложения хода. Явно названное место («во Inbox», «в дневник») важнее этого выбора. Просьба добавить задачу — [Задача по просьбе](#задача-по-просьбе).

| Что записать | Куда |
| --- | --- |
| Обязательство или действие | Inbox item по шагам ниже |
| Идея: возможность, «когда-нибудь подумать о…», без обязательства | `eva-notes`: одна строка с `#идея` в заметке дня |
| Мысль, наблюдение, запись о дне | `eva-notes`: заметка дня |
| Ссылка, пост, файл, «сохрани в базу», справка | `eva-notes`: захват — источник в `Источники/…` или адресная заметка домена; Входящие хранилища — если адрес неясен или захват не удался |
| Неясно | Inbox item: Triage разберёт |

Inbox item:

1. Возьми текст как есть: без Triage и чистовой формулировки.
2. Создай ровно один Inbox item через `task_create` без проекта, дат, приоритета, длительности и добавленного содержания. Даты и детали из текста оставь текстом. Если создание требует других значений, не назначай их по догадке.
3. Выполни Read-back.

Запись в Хранилище: загрузи `skill_view(name="eva-notes")`, затем `skill_view(name="eva-notes", file_path="references/write-policy.md")` и пиши по ним. Если `eva-notes` недоступен, назови это и одной строкой предложи записать во Inbox.

После записи — одна строка, что и куда записано; у Inbox item — его ID. Пользователь поправит место словами.

Обычный вопрос или справку без просьбы сохранить не записывай. Нет текста — спроси, что записать. Несколько явно названных записей — Группа операций: каждую направь по таблице, выполняй последовательно со стопом на первой ошибке. Поток всего, что владелец держит в голове, без явных команд записи — [Выгрузка из головы](brain-dump.md#выгрузка-из-головы).

## Triage

Один Inbox item за раз. Нужны чтение Inbox, задачи и дерева, изменение текста и места с сохранением ID.

1. Прочитай выбранный Inbox item и его ID. Если записей несколько и выбор не задан, включи выбор в блокирующие пробелы. Прочтение — ещё не завершённый Triage.
2. Определи тип: Задача, Проект, Идея, Справка или Встреча. Используй уже заданный тип; при неоднозначности оставь запись во Inbox до ответа.
3. Задача: используй заданные чистовую формулировку, первый доступный шаг и место по [дереву](tree.md); формулируй по [tasks.md](tasks.md#формулировка). Проект, Идею, Справку и Встречу веди по подразделам ниже.
4. Для Задачи измени исходный Inbox item через `task_update`/`task_move`, сохранив ID; копию прежней формулировки не создавай.
5. Read-back подтверждает место и тот же ID. Следующую запись разбирай, только если она входит в выбранный пользователем набор; такой набор веди последовательно без вопроса о продолжении. Без набора одной строкой предложи следующую по [переходам](signals.md#переходы-после-практик).

Отказ от формулировки оставляет запись без изменений. Отказ от самого обязательства — `task_cancel` по [tasks.md](tasks.md#состояние). Разобранную Идею, Справку или Встречу не удаляй и не отмечай выполненной: её Inbox item отменяется.

### Проект из Inbox item

Несколько самостоятельных действий ради одного результата — Проект.

1. Используй известные место и Следующий шаг по [projects.md](projects.md). Если шаг неизвестен, предложи конкретное действие по его определению.
2. Если подходящий Проект уже есть, предложи поместить Inbox item туда; дубликат проекта не создавай.
3. Новый Проект — Группа операций: `project_create` в выбранной Области по [projects.md](projects.md), получить ID, превратить исходный Inbox item в Следующий шаг и поместить в Проект. Preview набора, собранного агентом, показывает будущую привязку ID проекта и сохранение исходного ID задачи.
4. Дополнительный выбранный Следующий шаг включи в ту же группу.

При частичном результате может остаться Проект без шага, а исходная запись — во Inbox; покажи фактическое положение каждого объекта. Для режима `когда-нибудь` Следующий шаг не нужен; используй смысл и формулировку исходной записи и уточняй только блокирующую неоднозначность.

### Идея или Справка

Переносит агент через `eva-notes`: загрузи `skill_view(name="eva-notes")` и `skill_view(name="eva-notes", file_path="references/write-policy.md")`. Передай `eva-notes` текст Inbox item, его ID и дату создания, пересчитанную в `eva.timezone`. Идея — строка с `#идея` в заметке дня за эту дату; Справка — захватом: источник в `Источники/…` или адресная заметка домена, Входящие хранилища — если адрес неясен.

1. «Перенеси и отмени» при однозначном ID — запись через `eva-notes` и её проверка `read_file`, затем сразу `task_cancel` и Read-back.
2. «Перенеси» — запись и проверка, затем одна строка «Отменить Inbox item <ID>?» и отмена после «Да».
3. Без такой команды перенос — предложение агента: одна строка с назначением и отменой Inbox item; выполняй после «Да».
4. `task_cancel` — только после подтверждённой записи в Хранилище. Если запись не сделана или не проверена, Inbox item остаётся. Если отмена не удалась, сообщи: запись в Хранилище сделана, исходная запись не отменена или её состояние неизвестно. Без повтора и отката.
5. `eva-notes` недоступен — назови это; Inbox item не меняй.

Перенос пользователем вручную: пока он не сообщил о переносе, Inbox item не меняй; намерение перенести — не перенос. «Перенёс, отмени» при однозначном ID — сразу `task_cancel` и Read-back. Одно «перенёс» — одна строка «Отменить Inbox item <ID>?» и отмена после «Да». Это же действует для Встречи, которую пользователь перенёс в календарь сам.

### Встреча

Встреча — Inbox item с договорённостью и временем. Намерение без договорённости — Задача.

1. Передай Встречу `eva-calendar` с исходным ID и известными данными: загрузи его `skill_view(name="eva-calendar")`, затем `skill_view(name="eva-calendar", file_path="references/write-policy.md")` и создавай Событие по ним. Если скилл недоступен, назови ограничение и оставь Inbox item.
2. Недостающие поля События собирает `eva-calendar`. Если дата неизвестна или договорённости нет, одной строкой предложи сохранить это Задачей с действием уточнения и выполни после «Да».
3. Явная команда переноса — создание События и отмена Inbox item подряд без Preview; в наборе, собранном агентом, обе операции входят в один общий Preview.
4. `task_cancel` исходного ID и его Read-back выполняй только после того, как `eva-calendar` вернул созданное и перечитанное Событие (`applied`). Если Событие не создано или не подтверждено, Inbox item остаётся. Если отмена не удалась, сообщи: Событие создано, исходная запись не отменена или её состояние неизвестно. Без повтора и отката.

Слова пользователя не подтверждают незавершённую запись через `eva-calendar`; ручной перенос — по [правилу Идеи и Справки](#идея-или-справка).

## Inbox debt

Предложи отдельную сессию Triage с бюджетом по «Бюджетам практик» в `skill_view(name="eva", file_path="references/initiative.md")`. Прочитай Inbox через `task_list_inbox` и разбирай по одному по [Triage](#triage). В конце покажи остаток. Накопление Inbox Eva замечает сама и предлагает такую сессию по [signals.md](signals.md#сигналы-и-предложения).
