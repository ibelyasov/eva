# Служебные файлы Хранилища

`SCHEMA.md`, `AGENTS.md`, `index.md` и `log.md` лежат в корне Хранилища. Скилл создаёт их по шаблонам ниже один раз, когда Хранилище пусто: при первой записи или по просьбе «настрой хранилище». Это часть просьбы владельца; созданные файлы назови в Отчёте. Шаг основы «спросить домен вики» не нужен: домен задан шаблоном.

Порядок первичного создания:

1. `SCHEMA.md`, `index.md`, `log.md` — каждый с проверкой `read_file`.
2. Сама просьба владельца: мысль, ссылка, файл.
3. `AGENTS.md` — отдельной последней операцией, одним однофайловым вызовом `write_file`. Любая запись в `AGENTS.md` вызывает кнопку approval Hermes (защита инструкционных файлов, `--yolo` её не отключает): это ожидаемо и не даёт внедрить правила из захваченного текста. Предупреди владельца одной строкой перед записью. Любой ответ `BLOCKED` или отказ approval (отказ, timeout, недоставленный запрос, нет человека) — «Не сделано: AGENTS.md — Hermes не разрешил запись»; без повтора и без обхода через `terminal` или другие инструменты. Только для этого файла отказ не отменяет уже выполненную просьбу и не считается ошибкой группы.

- Хранилище, где кроме служебной папки `Eva/` (Журнал Eva) ничего нет, считается пустым: `Eva/` не трогай и создавай служебные файлы рядом.
- `SCHEMA.md` есть, а `AGENTS.md` нет — работай по скиллу. `AGENTS.md` создаётся по шаблону по просьбе «настрой хранилище», с тем же approval Hermes.
- Хранилище не пусто, а `SCHEMA.md` нет — не создавай поверх: покажи найденное и одной строкой предложи создать недостающие файлы, после «Да» создай их в порядке первичного создания: `AGENTS.md` последним, и его отказ не срывает остальное.
- Дальше `SCHEMA.md` меняется только с согласия владельца ([write-policy.md](write-policy.md#всегда-делай-так)), `AGENTS.md` в обычной работе не меняется ([write-policy.md](write-policy.md#agentsmd-хранилища)), `index.md` и `log.md` — по правилам `llm-wiki`.
- Шаблоны — стартовые: правила скилла важнее; если `SCHEMA.md` Хранилища противоречит скиллу, сообщи владельцу и действуй по скиллу.

## SCHEMA.md

````markdown
# Схема Хранилища

## Домен
Личная база знаний владельца: общая вики знаний по методу LLM-wiki, сферы жизни, работа, обучение, сообщества, проекты, дневник. Агент — основной писатель, владелец читает, комментирует и утверждает состав сущностей.

## Структура
- `Вики/` — Сущности, Понятия, Сравнения, Запросы, `_Карты/`, `_Архив/`: знания, имеющие смысл вне контекста.
- `Источники/` — Статьи, Публикации, Транскрипты, Файлы: сохранённые материалы, не переписываются.
- `Входящие/` — материал с неясным адресатом и неудачный захват.
- `Дневник/ГГГГ/ГГГГ-ММ-ДД.md`, недели — `Дневник/ГГГГ/ГГГГ-Www.md` (ISO-неделя).
- `Идеи/Идеи.md` — все идеи; `Идеи/<Название>.md` — развиваемая идея.
- `Проекты/`; `Жизнь/<Сфера>/`, привычки — `Жизнь/Мои привычки/`.
- `Работа/` — Вики, Источники, Проекты, Входящие с теми же ролями.
- `Обучение/<Курс>/<Курс>.md`, `Источники/`, `01 <Секция>/01 <Лекция>.md`; сегменты из названий — по разделу «Имена».
- `Сообщества/<Сообщество>/<Сообщество>.md`, `Курсы/`, `Материалы/`, `Обсуждения/`, `Источники/`.
- `Вложения/` — свои фото и картинки, вставленные в заметки.
- `Eva/` — Журнал Eva: служебная папка Eva (Пометки, Наблюдения, Практики, Лента). Не вики, не Входящие и не дневник: в `index.md`, `log.md`, lint и разбор не входит, её файлы агент Хранилища не переименовывает и не перемещает.
- Пустые папки заранее не создаются. Источник для нескольких доменов лежит в домене поступления.

## Имена
Русские, с большой буквы, уникальные в Хранилище. Имя файла — безопасная форма заголовка: символы `: ? * " < > | # ^ [ ] \ /` и управляющие заменяются, длинное имя обрезается до ≈ 100 символов; так же строятся папки из названий (сфера, курс, секция, сообщество, проект). Исходный заголовок — в H1 и `title`; без замен и обрезки имя файла совпадает с ним. Поля frontmatter — английские.

## Типы и поля
- Все контентные заметки: `type`, `origin` (`owner | source | agent`), `summary`; `aliases` — только настоящие RU/EN варианты; `tags` — из таксономии ниже.
- Wiki-типы `entity`, `concept`, `comparison`, `query`, `summary`: ещё `title`, `created`, `updated`, `tags`, `sources`; по условиям — `confidence`, `contested`, `contradictions`.
- `source`: `ingested`, `sha256` тела после frontmatter (у файла — байтов файла), `captured_at`, `capture: full | partial`; по возможности `source_url`, `author`, `title`.
- `habit`: `habitify_id`; `project`: `singularity_id`; у обоих по возможности `provider_url`.
- `course`: `url`, `community` у курса сообщества. `lecture`: `course`. `community`: `url`.
- `journal`: `date`; время события и получения — в строке записи. `inbox`: `received_at`, `channel`; неудачный захват — `capture: failed`. `idea`: без дополнительных полей.
- Даты — `ГГГГ-ММ-ДД`; моменты — RFC 3339 с поясом в кавычках; пояс дня — общий часовой пояс Eva. Ссылки в полях — wikilinks в кавычках.
- Новые `type` — расширение схемы. Lint вики проверяет требования wiki только у пяти wiki-типов.

## Происхождение и слова владельца
- Секции «Записи владельца» и «Комментарии владельца» агент не переписывает.
- Утверждения в агентских заметках — с маркерами `[extracted]`, `[inferred]`, `[ambiguous]` и ссылкой на основание, у каждого существенного утверждения.
- Противоречие — обе позиции с источниками и датами и `contested: true`. Новее не значит вернее.
- Изменённый источник — новый файл рядом, исходный не переписывается.

## План сущностей
Разбор начинается с плана: `+` — новая страница, `~` — изменение существующей, `→` — только ссылка. До ответа владельца разбор не пишется.

## Захват и разбор
Захват сохраняет материал без разбора: ссылка — полный доступный Markdown, картинки удалёнными ссылками. Разбор, lint и правки начинает владелец; автоматической обработки нет.
````

## AGENTS.md

````markdown
# Правила для агентов в Хранилище

- Работа с Хранилищем — только через скилл `eva-notes`. Служебную папку `Eva/` — Журнал Eva — ведёт Eva по справочнику навигатора `eva`; это не часть вики.
- Перед работой прочитай `SCHEMA.md` и этот файл.
- До утверждения Плана сущностей разбор не пишется.
- Слова владельца и его секции не меняются.
- Предположение не выдаётся за факт; связи не выдумываются.
- `.obsidian/` и `.livesync/` не трогаются.
- Отката нет: прежние версии — в истории Git.
````

## index.md

````markdown
# Индекс

> Каталог страниц вики: у каждой одна строка — wikilink и summary. Читай первым при поиске.
> Обновлено: ГГГГ-ММ-ДД | Страниц: 0

## Разделы
- `Дневник/` · `Входящие/` · `Источники/` · `Проекты/` · `Жизнь/` · `Работа/` · `Обучение/` · `Сообщества/`

## Сущности

## Понятия

## Сравнения

## Запросы

## Работа
````

- В секции wiki-типов попадают страницы `Вики/`, в «Работа» — страницы `Работа/Вики/`; внутри секции — по алфавиту. Доменные заметки, источники, дни и файлы `Eva/` в индекс не вносятся.
- Ссылку `[[Идеи/Идеи|Идеи]]` добавь в «Разделы», когда страница появится.
- Масштаб — по основе: секция больше 50 строк делится, индекс больше 200 строк — карты в `Вики/_Карты/`.

## log.md

````markdown
# Хронология операций

> Только дописывается.
> Формат: `## [ГГГГ-ММ-ДД] action | subject`
> Actions: create, capture, ingest, update, query, lint, archive, delete, schema
> После 500 записей файл переименовывается в `log-ГГГГ.md` (занято — `log-ГГГГ-2.md`, `log-ГГГГ-3.md`) и начинается заново.

## [ГГГГ-ММ-ДД] create | Хранилище подготовлено
- Созданы SCHEMA.md, index.md, log.md
````

В `log.md` пишутся операции вики, захват источников, сохранённые ответы, массовые правки и изменения `SCHEMA.md` с перечнем файлов. Строки дневника, идеи, создание `AGENTS.md`, записи Журнала Eva в `Eva/` и вопросы без сохранения ответа не пишутся.
