# Вики поверх `llm-wiki`

Основа — скилл `llm-wiki` без изменений; файловые приёмы — скилл `obsidian`; где их взять — [tools.md](tools.md#основы). Корень Хранилища для обоих — по [tools.md](tools.md#корень-хранилища): их собственный поиск пути и запасные `~/wiki`, `~/Documents/Obsidian Vault` не действуют. Всё, что ниже не переопределено, работает как в основе: ориентация в начале сессии, пороги «10+» и «2 ссылки», порог создания сущности, поиск и ответ шага query (без записи — п. 8), lint (без запуска кода — п. 9), `index.md`, `log.md` и его ротация.

## Переопределения

1. **Структура.** Вместо английских папок основы — русские папки Хранилища; служебные `SCHEMA.md`, `index.md`, `log.md` и `AGENTS.md` лежат в корне под своими именами.

   | `llm-wiki` | Хранилище |
   | --- | --- |
   | `entities/` | `Вики/Сущности/` |
   | `concepts/` | `Вики/Понятия/` |
   | `comparisons/` | `Вики/Сравнения/` |
   | `queries/` | `Вики/Запросы/` |
   | `_meta/topic-map.md` | `Вики/_Карты/` |
   | `_archive/` | `Вики/_Архив/` |
   | `raw/articles/` | `Источники/Статьи/` |
   | `raw/papers/` | `Источники/Публикации/` |
   | `raw/transcripts/` | `Источники/Транскрипты/` |
   | `raw/assets/` | `Источники/Файлы/` |

   Доменные `Источники/` (`Работа/Источники/`, `Обучение/<Курс>/Источники/`, `Сообщества/<Сообщество>/Источники/`) и `Работа/Вики/` повторяют те же роли. Карта доменов — [areas.md](areas.md). Пустые папки заранее не создавай; `Вики/_Карты/` появляются по правилу масштаба `index.md` основы.
2. **План сущностей** `+ ~ →` перед любой записью разбора, включая конспекты, по [write-policy.md](write-policy.md#план-сущностей). Он расширяет шаг «Discuss takeaways» и действует в любом режиме: пропуск шага в автоматическом режиме отменён.
3. **Разбор начинает владелец.** Заданий по расписанию и автоматической обработки Входящих хранилища, дневника, PDF и фото нет.
4. **Ответ на вопрос** сохраняется в `Вики/Запросы/` или `Вики/Сравнения/` только по просьбе владельца. Автосохранение «ценных» ответов отключено; агент может одной строкой предложить сохранить.
5. **Headless-настройка** (Obsidian Sync, `obsidian-headless`, Node, systemd, вход в аккаунты) не выполняется: синхронизацией управляет окружение.
6. **Изменённый источник** — новый файл рядом, исходный не переписывается: правило основы «flag drift and update» заменено. В правилах обновления «newer sources generally supersede» заменено: новее не значит вернее, противоречие — обе позиции с `contested: true`.
7. **Происхождение.** `origin`, сохраняемые секции владельца, маркеры `[extracted]`, `[inferred]`, `[ambiguous]` и ссылка на основание у каждого существенного утверждения — независимо от числа источников, а не только при 3+ ([fields.md](fields.md#маркеры-утверждений)).
8. **Вопрос только читает.** Шаг Query основы «Update log.md» отменён: ответ на вопрос не меняет ни `log.md`, ни другие файлы. Строка `query` в `log.md` пишется только вместе с сохранением ответа страницей по п. 4. Фоновый запуск заметки не пишет.
9. **Lint без запуска кода.** Шаги основы, которые предлагают `execute_code` (сироты, битые ссылки), выполняй поиском, чтением файлов и `rg` в оболочке; запуск кода скиллу не нужен.
10. **URL** — по правилам захвата [capture.md](capture.md#ссылка): полный доступный текст, без wiki-разбора при захвате, без загрузки картинок. Шаг основы «URL → извлечь текст → `raw/articles/`» заменён им.
11. **Служебные папки вне вики.** `Eva/` — Журнал Eva ([write-policy.md](write-policy.md#журнал-eva)); `.obsidian/`, `.livesync/` — Obsidian и синхронизация; `.agents/`, `.claude/` — файлы скиллов. Они не вносятся в `index.md` и `log.md`, не проверяются lint, не разбираются, не служат источником знаний в ответах по базе, не архивируются и не правятся; ссылки из них не считаются связями страниц.
12. **Состояние Разбора у источника.** Правило основы «never modify files in `raw/`» действует для тела и всех полей источника, кроме `processing` во frontmatter ([fields.md](fields.md#по-типам)): `pending` ставит захват, `done` — Разбор, `skipped` — слова владельца. Других правок источника нет; `sha256` считается по телу и от поля не меняется. Захват здесь отделён от Разбора, и без поля неразобранное одним поиском не найти.

Ещё отличия от основы:

- Имена заметок — русские, с большой буквы, с пробелами; имя файла уникально в Хранилище и совпадает с H1 и `title`, кроме изменений по [правилу имён](fields.md#имена-файлов-и-папок). Правило основы «lowercase, hyphens» не действует.
- Поля — по [fields.md](fields.md); `type` основы (`entity | concept | comparison | query | summary`) не переименовываются, доменные типы — расширение схемы.
- `log.md` получает операции вики, захват источников, массовые правки и изменения `SCHEMA.md`; строки дневника, идеи, записи `Eva/` и вопросы без сохранения ответа в него не пишутся.
- Шаг инициализации «спросить домен вики» заменён: домен задан шаблоном [vault-files.md](vault-files.md).

## Общее и доменное

- В `Вики/` — то, что имеет смысл вне контекста: вещество, понятие, технология, метод, публичная персона.
- В домене — то, что живёт в контексте: конспект лекции, синтез по курсу, материалы и обсуждения сообщества, рабочие сущности (клиенты, коллеги, внутренние системы) в `Работа/Вики/`.
- Доменная заметка ссылается на общую сущность, а не копирует её. Обогащение общей сущности фактами из лекции — строкой `~` в Плане сущностей.
- Источник для нескольких доменов лежит в домене поступления, остальные ссылаются на него.

## Разбор

Разбор (ingest основы) начинает владелец: «разбери статью», «сделай конспект лекции», «разбери материал сообщества».

1. Ориентация по основе: `SCHEMA.md`, `AGENTS.md`, `index.md`, конец `log.md`; поиск существующих страниц по названиям и `aliases`.
2. Материал должен быть сохранён источником. Ещё не сохранён — сначала захват по [capture.md](capture.md); это запись по явной просьбе, план для неё не нужен.
3. План сущностей и ответ владельца по [write-policy.md](write-policy.md#план-сущностей).
4. Утверждённые страницы — по основе: пороги, минимум 2 осмысленные ссылки у новой или обновлённой страницы, теги из таксономии `SCHEMA.md`, `confidence` по основе, переопределения 6–7. Конспект лекции — в домене по [areas.md](areas.md#обучение).
5. `index.md` и запись `log.md` вида `## [ГГГГ-ММ-ДД] ingest | <Материал>` с перечнем файлов.
6. Последней записью — `processing: done` точечной правкой frontmatter у каждого источника, чьи страницы, `index.md` и `log.md` записаны; так же, если по Плану материал остался источником. Остальные источники при ошибке на более раннем шаге остаются `pending`, в Отчёте «не сделано». Владелец ответил на План, что разбор не нужен («для справки», «не разбирай»), — `skipped`, и это единственная запись: страниц, `index.md` и `log.md` нет. Отказ от Плана без этих слов поле не меняет.
7. Проверка каждой записи и Отчёт по [write-policy.md](write-policy.md#проверка-и-отчёт).

## Неразобранное

«Что не разобрано» — только чтение, без записей:

1. Источники: поиск строки `processing: pending` в папках `Источники/` Хранилища, общей и доменных; `Eva/` и служебные папки (п. 11) в поиск не входят. В оболочке: `rg -l --no-ignore-vcs '^processing: pending\r?$' -g '**/Источники/**' "<корень>"`. Покажи путь, `summary` и `captured_at`, старые первыми.
2. Отдельно — заметки `Входящие/` и `Работа/Входящие/`: их неразобранность — сама папка, поля `processing` у них нет.
3. Источники без `processing` этот поиск не находит — их показывает [lint](#lint).

Разбор по списку начинает владелец, по одному материалу или названной группе.

## Вопрос

1. Прочитай `index.md` и карты `Вики/_Карты/`. Ищи по Хранилищу без `Eva/` и служебных папок (п. 11) всегда, не только при 100+ страницах: по названию, `aliases` на русском и английском и нескольким формулировкам — русская морфология ломает точное совпадение.
2. Прочитай найденные заметки и ответь со ссылками `[[…]]` на них.
3. Отдели «найдено в базе» от внешнего знания. Отсутствие совпадений не доказывает отсутствие факта: назови, что и где искал.
4. Ответ — только чтение: `log.md` и другие файлы не меняются. Сохранение ответа — только по просьбе владельца; тогда страница `type: query` или `comparison` с `origin: agent` в `Вики/Запросы/` или `Вики/Сравнения/`, строка в `index.md` и строка `query` в `log.md`.

## Lint

По просьбе владельца — шаги lint основы с уточнениями:

- Проверка frontmatter, таксономии тегов, устаревания и сирот — только для пяти wiki-типов (`entity`, `concept`, `comparison`, `query`, `summary`) в `Вики/` и `Работа/Вики/`. Заметки расширенных типов по требованиям wiki не проверяй; `Eva/` и служебные папки в lint не входят.
- Source drift — для источников с `sha256`: пересчитай хэш тела (`sed '1,/^---$/d' "<путь>" | sha256sum`) и сравни. Несовпадение говорит о локальной правке файла, а не об изменении удалённой страницы.
- Покажи все страницы с `contested: true`, `contradictions` и `confidence: low`.
- Источник (`type: source`) без `processing` или с другим значением, чем `pending | done | skipped`, — находка. Предложи значение: `done`, если путь или wikilink источника есть в записи `ingest` `log.md` и его архивов `log-ГГГГ*.md` или в `sources` страниц, иначе `pending`. Проставляет его массовая правка по просьбе.
- Ротация `log.md` после 500 записей — по основе, в `log-ГГГГ.md`; занято — `log-ГГГГ-2.md` и далее, `mv -n`.
- Отчёт lint — находки с путями по степени важности и предлагаемые действия. Исправления — только по просьбе, как массовая правка по [write-policy.md](write-policy.md#массовая-правка).
- Запись в `log.md`: `## [ГГГГ-ММ-ДД] lint | N находок`.

## Архив

Перемещение страницы в `Вики/_Архив/` — по правилу архива основы с сохранением подпапки; файл переноси `mv -n` в оболочке на свободный путь ([без перезаписи](write-policy.md#без-перезаписи)), ссылки на него заменяй текстом с пометкой «(в архиве)». Только по явной просьбе или после «Да» на предложение.
