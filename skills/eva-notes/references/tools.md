# Инструменты и окружение

Скилл пользуется встроенными инструментами Hermes; MCP не нужен. Ожидаемый набор задан в `tools.json` (загрузка — `skill_view(name="eva-notes", file_path="tools.json")`): `toolset` — встроенный toolset Hermes, `name` — имя инструмента, `access` — `read` или `write`, `optional: true` — инструмент нужен не всем сценариям; остальные обязательны.

## Состав

| Toolset | Инструмент | access | Для чего |
| --- | --- | --- | --- |
| `file` | `read_file` | read | Чтение заметок, служебных файлов, кэша; проверка после записи |
| `file` | `search_files` | read | Поиск файлов и текста в Хранилище |
| `file` | `write_file` | write | Новая заметка или полная перезапись |
| `file` | `patch` | write | Точечная правка по свежему тексту |
| `terminal` | `terminal` | write | Корень Хранилища, `test -e`, `sha256sum`, `cp -n` и `mv -n` файлов, `diff`, `rg` |
| `web` | `web_extract` | read | Текст страницы по ссылке; не обязателен |
| `skills` | `skill_view` | read | `llm-wiki`, `obsidian`, файлы скилла, соседние скиллы |
| `skills` | `skills_list` | read | Поиск внешнего `grill-me`; не обязателен |
| `clarify` | `clarify` | read | План сущностей, блокирующие пробелы, карточка согласия |

`memory` и `execute_code` скилл не использует: lint основы выполняется `search_files`, `read_file` и `terminal`.

Ответ `write_file` с `verified:true` и советом не перечитывать файл не отменяет проверку `read_file`: она сверяет путь, frontmatter и фрагмент с разрешённым, а не только факт записи.

## Корень Хранилища

- Путь задаёт Потребитель переменными окружения `OBSIDIAN_VAULT_PATH` и `WIKI_PATH`; обе указывают на корень Хранилища. Файловые инструменты переменные не раскрывают: один раз прочитай значения через `terminal` (`printenv OBSIDIAN_VAULT_PATH WIKI_PATH`) и дальше передавай абсолютные пути. В песочнице переменные видны, только если Потребитель передал их в контейнер (`terminal.docker_forward_env` или `terminal.docker_env`) со значениями — путями внутри песочницы.
- Переменные не заданы или указывают на разные каталоги — сценарий не начинай: назови переменные и рекомендуй Потребителю задать их. Запасные пути основ (`~/wiki`, `~/Documents/Obsidian Vault`) не используй.
- Имена файлов содержат пробелы и кириллицу: в `terminal` бери пути в кавычки, в остальном предпочитай файловые инструменты.

## Песочница

- `file` и `terminal` исполняются в одноразовом Docker-контейнере без сети. Хранилище смонтировано на запись; `.obsidian/` и `.livesync/` — только на чтение, их не меняй.
- В образе есть `bash`, coreutils, `rg`, `jq`, `diff`, `patch`, Python. Node, curl и git нет; ничего не устанавливай и не ходи в сеть из `terminal`.
- Синхронизацию LiveSync и журнал версий Git ведёт окружение. Скилл их не настраивает и не вызывает.

## `web_extract` и кэш

- `web_extract` исполняет сам Hermes вне песочницы; провайдера выбирает Потребитель. Ответ — Markdown, картинки остаются удалёнными ссылками.
- Модель видит до `web.extract_char_limit` символов: по умолчанию 15 000, значение задаёт Потребитель. Длинная страница приходит началом и концом с подвалом `[TRUNCATED]`; строка подвала `Full text saved to: <путь>` называет файл полного текста в кэше (в песочнице под `/root/.hermes/cache/web/`, только чтение).
- Файл кэша назван по URL и перезаписывается при повторном извлечении того же адреса: копируй его в Хранилище сразу после вызова.
- Подвал ответа «Full text could not be stored» — полного текста нет, захват `partial`. Пометка `[... stored copy truncated at …]` стоит не в ответе, а в конце самого файла кэша (копия длиннее 2 000 000 символов): проверь хвост файла перед копированием; есть пометка — захват `partial`, после `cat >>` она остаётся последней строкой тела.
- Повторное извлечение того же URL в пределах TTL кэша Hermes (по умолчанию 20 минут) возвращает сохранённый результат: это не новая версия страницы.

## Вложения Telegram

- Фото и документы Hermes кладёт в свой кэш (`cache/images`, `cache/documents`; в песочнице под `/root/.hermes/cache/`, только чтение). Путь бери из сообщения Hermes о вложении.
- Фото модель видит напрямую; документ не читай и не распознавай без просьбы владельца.
- У пересланных сообщений автор может теряться; такой текст не выдавай за слова владельца.

## sha256

Хэш считай в `terminal`:

- файл кэша или вложение целиком: `sha256sum "<путь>"`;
- тело сохранённой заметки после frontmatter: `sed '1,/^---$/d' "<путь>" | sha256sum`.

## status

Без записей покажи:

- корень Хранилища и совпадение `OBSIDIAN_VAULT_PATH` и `WIKI_PATH`;
- загружаются ли `llm-wiki` и `obsidian`;
- есть ли `SCHEMA.md`, `AGENTS.md`, `index.md`, `log.md`; число записей `log.md`;
- `eva.notes.vault_name` и `eva.timezone` из блока `[Skill config …]`;
- доступность инструментов из `tools.json`.

## Нет инструмента

Если нет нужного инструмента, скажи: «Не могу выполнить <сценарий>: в Hermes нет <toolset/имя>. <Что прочитано и что осталось без изменения>». Назови недостающие имена и рекомендуй включить их toolset в Hermes. Скилл ничего не устанавливает и не настраивает.

- Нет `web_extract` или он вернул ошибку — ссылка уходит во Входящие хранилища с `capture: failed` по [capture.md](capture.md#сбой); другого провайдера не подставляй.
- Нет `write_file` или `patch` — только чтение и ответы.
- Нет `terminal` — нельзя определить корень Хранилища и посчитать `sha256`: если корень неизвестен, сценарий не начинай; иначе файлы не копируй и источники не сохраняй, запись в заметки продолжай.
- Нет `clarify` — разбор, предложения агента и блокирующие пробелы не выполняй.
- Нет `skills_list` — `grill-me` не найти: назови его и рекомендуй установить в Hermes.
