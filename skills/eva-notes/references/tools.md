# Инструменты и окружение

Скилл работает файловыми инструментами и оболочкой хоста; MCP и собственный код ему не нужны. Остальные файлы скилла называют действия, а не имена инструментов: у каждого хоста имена свои. Особенности Hermes — в разделе [Hermes](#hermes). Ссылки между файлами `references/` ведут в ту же папку `references/` каталога скилла.

## Действия

| Действие | Для чего | Нет действия |
| --- | --- | --- |
| Прочитать файл | Заметки, служебные файлы, файлы скиллов; проверка после записи | Сценарий не начинай |
| Найти | Файлы по имени и текст в Хранилище | Сценарий не начинай |
| Записать файл | Новая заметка или полная перезапись | Только чтение и ответы |
| Поправить | Точечная правка существующего файла по свежему тексту | Только чтение и ответы |
| Выполнить команду | POSIX-оболочка: `pwd`, переменные окружения, `test -e`, `sha256sum`, `cp -n`, `mv -n`, `diff`, `rg`, `tail` | См. [Нет действия](#нет-действия) |
| Извлечь текст страницы | Текст страницы по ссылке | Захват ссылки `partial` по [capture.md](capture.md#без-извлечения) |
| Задать вопрос | Блокирующие пробелы, План сущностей, карточка «Да»/«Нет» | Обычный вопрос в чате |
| Загрузить скилл | Соседние скиллы Eva, `grill-me`, основы без копий в Хранилище ([Основы](#основы)): инструментом скиллов хоста по имени; такого инструмента нет — найди скилл в списке скиллов, который дал хост, или в том же каталоге скиллов, где лежит этот скилл, и прочитай его `SKILL.md` | Скилл не установлен: назови его и рекомендуй установить |

- Вопрос владельцу — карточкой выбора, если хост её даёт, иначе обычным сообщением в чате. Timeout, пропуск и пустой ответ — не ответ и не согласие.
- Память хоста (`memory`) и запуск кода (`execute_code`) скилл не использует: lint основы выполняется поиском, чтением и командами оболочки.

## Корень Хранилища

Определи корень один раз, до первого чтения заметок:

1. Задана переменная окружения `OBSIDIAN_VAULT_PATH` или `WIKI_PATH` — корень из неё; значения узнай командой оболочки. Заданы обе и указывают на разные каталоги — стоп: назови переменные и попроси указать в обеих корень Хранилища.
2. Ни одна не задана — корень = рабочий каталог, если в нём есть папка `.obsidian/`; абсолютный путь — `pwd`.
3. Иначе — стоп: попроси владельца открыть агента в корне Хранилища, в папке с `.obsidian/`.

- Дальше передавай инструментам абсолютные пути от корня: файловые инструменты переменные не раскрывают, а относительный путь хост может разрешить не от корня.
- Основам `llm-wiki` и `obsidian` передавай этот корень явно. Их собственные правила поиска пути и запасные `~/wiki`, `~/Documents/Obsidian Vault` не используй.
- Имена файлов содержат пробелы и кириллицу: в командах бери пути в кавычки, в остальном предпочитай файловые инструменты.
- Синхронизацию Хранилища и историю версий Git ведёт окружение; скилл их не настраивает и не вызывает. В оболочке ничего не устанавливай.

## Основы

`llm-wiki` и `obsidian` — основы скилла. Найди каждую после корня Хранилища:

1. В Hermes — встроенный скилл по имени ([Hermes](#hermes)).
2. Иначе — копия Отдельной установки: прочитай целиком `<корень>/.agents/eva-notes-bases/llm-wiki/SKILL.md` и `<корень>/.agents/eva-notes-bases/obsidian/SKILL.md`. Это неизменённые тексты Hermes, а не скиллы клиента: их кладёт Установщик, и клиент сам их не выбирает.
3. Копии нет — загрузи скилл с этим именем ([Загрузить скилл](#действия)), если хост его даёт. Это скилл клиента, а не копия Отдельной установки и не встроенный скилл Hermes: назови это владельцу в первом ответе — его устройство может отличаться от закреплённой версии, на которую рассчитаны переопределения.
4. Нет ни копии, ни скилла — основы нет: [Нет действия](#нет-действия).

Основы написаны для Hermes и называют его инструменты: их шаги выполняй [действиями](#действия) этого хоста, с переопределениями [wiki.md](wiki.md).

## Извлечение страницы

- `capture: full` — только когда инструмент вернул полный текст страницы. Пересказ, выжимка или ответ на вопрос о странице — `capture: partial`.
- Длинный ответ хост может усечь и сохранить полный текст в файл, назвав путь. Тогда тело источника бери из этого файла сразу после вызова: файл может перезаписаться. Хост пометил сохранённую копию усечённой или полный текст не сохранён — `capture: partial`.
- Повторное извлечение того же адреса может вернуть сохранённый хостом результат: это не новая версия страницы.
- Картинки не скачивай. Страницу в оболочке не загружай и другой способ извлечения не подставляй.

## Вложения

- Фото или документ, присланный в разговоре, хост сохраняет в файл и называет путь: бери файл оттуда. Путь неизвестен — файл не сохраняй и скажи об этом.
- Фото модель видит напрямую; документ не читай и не распознавай без просьбы владельца.
- У пересланных сообщений автор может теряться; такой текст не выдавай за слова владельца.

## sha256

Хэш считай командой оболочки:

- файл полного текста или вложение целиком: `sha256sum "<путь>"`;
- тело сохранённой заметки после frontmatter: `sed '1,/^---$/d' "<путь>" | sha256sum`.

## status

Без записей покажи:

- корень Хранилища и откуда он взят: переменная или рабочий каталог;
- откуда взяты основы `llm-wiki` и `obsidian`: копии в Хранилище или скиллы хоста; какой нет;
- какие соседние скиллы установлены: `eva`, `eva-tasks`, `eva-habits`, `grill-me`;
- есть ли `SCHEMA.md`, `AGENTS.md`, `index.md`, `log.md`; число записей `log.md`;
- число неразобранных источников и заметок Входящих хранилища — поиском по [wiki.md](wiki.md#неразобранное);
- `eva.notes.vault_name` и `eva.timezone` из блока Предпочтений навигатора; блока нет — «пояс дня — местный пояс машины агента, ссылки `obsidian://` не пишутся»;
- каких [действий](#действия) нет.

## Нет действия

Если нет нужного действия, скажи: «Не могу выполнить <сценарий>: у агента нет действия «<действие>». <Что прочитано и что осталось без изменения>». Рекомендуй подключить недостающий инструмент в хосте. Скилл ничего не устанавливает и не настраивает.

- Нет извлечения страницы — захват ссылки `partial` по [capture.md](capture.md#без-извлечения).
- Нет записи или правки — только чтение и ответы.
- Нет выполнения команд — переменные окружения не узнать: корень — рабочий каталог с `.obsidian/`, если хост назвал его абсолютный путь, иначе сценарий не начинай. Хэш не посчитать: файлы не копируй и источники не сохраняй, запись в заметки продолжай.
- Нет инструмента вопроса — спрашивай обычным сообщением в чате.
- Соседний скилл не найден — назови его и рекомендуй установить. Основа не найдена — назови её и рекомендуй поставить по разделу отдельной установки `SETUP.md` Eva; в Hermes — включить встроенный скилл.

## Hermes

В Hermes v0.21.6 ожидаемые инструменты перечислены в `tools.json` этого скилла: `toolset` — встроенный toolset Hermes, `name` — имя инструмента, `access` — `read` или `write`, `optional: true` — нужен не всем сценариям. Нет инструмента — назови его имя и toolset и рекомендуй включить toolset в Hermes.

| Действие | Hermes |
| --- | --- |
| Прочитать файл, найти | `read_file`, `search_files` (toolset `file`) |
| Записать файл, поправить | `write_file`, `patch` (toolset `file`) |
| Выполнить команду | `terminal` |
| Извлечь текст страницы | `web_extract` (toolset `web`) |
| Задать вопрос | `clarify`: карточка — `question` с полным текстом и `choices` «Да», «Нет»; свободный ответ — без `choices`. «Other» без явного «да» — не согласие |
| Загрузить скилл | `skill_view(name="eva-tasks")`; поиск `grill-me` — `skills_list`, затем `skill_view(name="grill-me")` |

- Основы — встроенные скиллы Hermes: `skill_view(name="llm-wiki")`, `skill_view(name="obsidian")`. Каталог `.agents/eva-notes-bases/` Хранилища в Hermes не читай.
- Файлы скилла: `skill_view(name="eva-notes", file_path="references/<файл>.md")`, контракт — `file_path="tools.json"`; файл соседа — `skill_view(name="eva", file_path="references/notebook.md")`. Markdown-ссылка файл не загружает; `read_file` с относительным путём прочтёт файл Хранилища, а не скилла.
- Блок Предпочтений — `[Skill config …]` навигатора `eva`, загруженного через `skills.auto_load`.
- Корень: Потребитель задаёт `OBSIDIAN_VAULT_PATH` и `WIKI_PATH`; прочитай их `printenv OBSIDIAN_VAULT_PATH WIKI_PATH` в `terminal`. В песочнице переменные видны, только если Потребитель передал их в контейнер (`terminal.docker_forward_env` или `terminal.docker_env`) со значениями — путями внутри песочницы.
- Песочница: `file` и `terminal` исполняются в одноразовом Docker-контейнере без сети. Хранилище смонтировано на запись; `.obsidian/` и `.livesync/` — только на чтение. В образе есть `bash`, coreutils, `rg`, `jq`, `diff`, `patch`, Python; Node, curl и git нет.
- Файлы скиллов не меняй: `skill_manage` не вызывай, даже если Hermes его предлагает.
- Ответ `write_file` с `verified:true` и советом не перечитывать файл не отменяет проверку чтением.
- `AGENTS.md`: каждая запись `write_file` или `patch` в него вызывает кнопку approval Hermes — Hermes защищает инструкционные файлы, `--yolo` это не отключает. Пиши его отдельным однофайловым вызовом, не многофайловым `patch`: один защищённый файл блокирует весь вызов. Ответ `BLOCKED` или отказ approval — «Не сделано: AGENTS.md — Hermes не разрешил запись».
- `web_extract` исполняет сам Hermes вне песочницы; провайдера выбирает Потребитель. Ответ — Markdown, картинки — удалёнными ссылками. Модель видит до `web.extract_char_limit` символов (по умолчанию 15 000).
- Длинная страница приходит началом и концом с подвалом `[TRUNCATED]`; строка подвала `Full text saved to: <путь>` называет файл полного текста в кэше (в песочнице под `/root/.hermes/cache/web/`, только чтение). Файл назван по URL и перезаписывается при повторном извлечении: допиши тело в заметку сразу (`cat "<кэш>" >> "<заметка>"`).
- Подвал «Full text could not be stored» — полного текста нет, `capture: partial`. Пометка `[... stored copy truncated at …]` стоит в конце самого файла кэша (копия длиннее 2 000 000 символов): проверь хвост `tail -c 400 "<кэш>"` перед копированием; есть пометка — `capture: partial`, после `cat >>` она остаётся последней строкой тела.
- Повторное извлечение того же URL в пределах TTL кэша (по умолчанию 20 минут) возвращает сохранённый результат.
- Вложения Telegram Hermes кладёт в свой кэш (`cache/images`, `cache/documents`; в песочнице под `/root/.hermes/cache/`, только чтение); путь — из сообщения Hermes о вложении.
