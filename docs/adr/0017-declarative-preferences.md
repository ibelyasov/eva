# Предпочтения задаются при подключении, пометки объектов — в работе

Настройки Eva делятся по происхождению.

**Предпочтения** задаются один раз и не возникают из работы с объектами провайдеров: часовой пояс (один на все скиллы), рабочие дни, стиль названий привычек, календарь записи и календари чтения, границы дня, зазор, напоминания Событий, Броней и Распорядка, имя Хранилища Obsidian для ссылок `obsidian://` (`eva.notes.vault_name`, без default: не задано — обратная ссылка только читаемым путём, [ADR 0021](0021-provider-back-links.md)), лимит Инициатив в день (`eva.initiative.daily_limit`, default 10, [ADR 0022](0022-eva-journal-and-initiative.md)). Путь Хранилища — не предпочтение: его задают переменные окружения `WIKI_PATH` и `OBSIDIAN_VAULT_PATH` ([ADR 0016](0016-consumer-boundary.md)). Их значения Потребитель определяет при подключении в диалоге владельца со своим агентом и задаёт декларативно в профильном `config.yaml` Хоста, в `skills.config`. Ключи объявляет навигатор `eva` в `metadata.hermes.config`; Потребитель включает его в `skills.auto_load`, поэтому карта скиллов и разрешённые значения всегда есть в контексте. Остальные скиллы читают значения из этого блока и не записывают их ни в Журнал Eva, ни в `memory`, ни в файлы. Просьбу изменить предпочтение в чате скилл не выполняет: называет ключ и новое значение для Потребителя и, если нужно, применяет его только в текущем разговоре.

**Пометки объектов** — Режимы поддерева Областей и Папок SingularityApp и Области Habitify, выбранные как Ритуалы, с первой привычкой — возникают в работе вместе с объектами. Их пишет скилл-владелец в `Eva/Пометки.md` Журнала Eva по ходу сценария: когда сценарию не хватает пометки, он спрашивает в этот момент с рекомендацией и сохраняет ответ ([ADR 0006](0006-state-in-eva-journal.md)). Отдельного setup в чате нет.

**Ритм** — задания cron Хоста, которые Потребитель создаёт и сопровождает по шаблонам [`SETUP.md`](../../SETUP.md): Рефлексия, утро, Дневная проверка и закрытие дня ([ADR 0022](0022-eva-journal-and-initiative.md)); доставку адресует явно. Задания Ритма Eva не создаёт и не удаляет и по своей инициативе не меняет; по явной просьбе владельца она выставляет у названного задания Ритма только `attach_to_session`, потому что CLI Hermes его не задаёт. Сама она ставит только Возвраты ([ADR 0003](0003-no-unattended-writes.md)). Утро зовёт к Daily open, в день Weekly — к Weekly, в первый Weekly месяца — ещё к модулю Когда-нибудь, и называет наступившие Обзоры экспериментов. Состав по дате выбирает модель по тексту задания: cron Hermes не выражает «первый такой-то день недели месяца», а день месяца и день недели в нём объединяются через «или». День Weekly и другие значения расписания Потребитель подставляет в текст задания; отдельных ключей для них нет. Шаблон задания задаёт цель и голос, а не чек-лист: содержание и процедуру даёт навигатор `eva`.

**Контракт setup** — [`SETUP.md`](../../SETUP.md): ключи, смысл, рекомендуемое значение или правило его вывода из фактов о человеке, основание с уровнем доказательности, альтернативы, настройки cron Hermes, шаблоны заданий Ритма и рекомендуемые уровни моделей для них. Основания рекомендаций — [досье setup](../../research/setup.md) и, для Ритма и лимита Инициатив, [досье проактивности](../../research/agents/proactivity.md). Агент Потребителя рекомендует, а не спрашивает «когда удобно»; спрашивает только факты, которые знает лишь человек; сначала обсуждает рекомендацию текстом, затем получает одно подтверждение.

## Considered Options

- Хранить все настройки в `memory` и проводить setup в чате: значения зависят от модели в мессенджере, setup превращается в анкету, а расписания нельзя адресовать в нужную тему без участия человека.
- Объявить ключи в каждом провайдерном скилле: обычный `skill_view` Hermes v0.21.6 не подставляет значения `skills.config`; пришлось бы постоянно загружать все полные скиллы с ключами.
- Отдельный маленький скилл настроек: ещё один скилл ради носителя; навигатор и так отвечает за общую карту.
- Задавать пометки объектов декларативно: каждая новая Папка или Ритуал требовали бы деплоя, а ID Областей появляются только после их создания в провайдере.
- `SOUL.md`, файлы контекста или заполненная Потребителем `memory`: смешивают настройки с характером Хоста, зависят от рабочего каталога или делают изменяемое состояние источником декларации.
- Отдельные ключи для расписания и состава Ритма: значения расписания живут в заданиях cron, которые Потребитель и так задаёт; второй источник расходился бы с ними.

## Consequences

Hermes печатает значения блока как текст и показывает пустые и ложные значения (`0`, `false`, `[]`, `{}`, `''`) как `(not set)`, поэтому ключи устроены так, что «не задано» и пустое значение совпадают по смыслу. Для незаданного предпочтения действует default, описанный для ключа; если default нет и значение блокирует сценарий, скилл спрашивает его одним `clarify` для текущего разговора и называет ключ, который нужно задать у Потребителя. Ненужное сценарию не спрашивается. `eva.initiative.daily_limit = 0` Hermes показывает как `(not set)`, и действует default 10: выключить фоновую Инициативу можно только тем, что не создавать задания Ритма.

`metadata.hermes.config` несовместим с portable plugin loader, поэтому Eva подключается только каталогом через `skills.external_dirs`, без plugin manifest ([ADR 0005](0005-hermes-host-connections.md)). Штатных `hermes plugins validate` и `doctor` для такого каталога нет: CI проверяет `git diff --check`, остальное — независимое ревью; валидность frontmatter, security scan и discovery до появления штатной проверки Hermes автоматически не проверяются.

Навигатор загружается всегда, но не становится обязательным шагом перед каждым запросом ([ADR 0011](0011-navigator-always-loaded.md)). Значения подставляются при создании экземпляра агента Хоста: после изменения `skills.config` нужен новый экземпляр (например, перезапуск gateway). Задание Ритма и Возврат прикрепляют `eva` вместе со скиллами сценария. Часовой пояс Eva и часовой пояс Хоста, по которому считается cron, — разные входы; Потребитель задаёт их согласованно.

`memory` Hermes Eva не использует ([ADR 0006](0006-state-in-eva-journal.md)). Записи предпочтений в Журнал или `memory`, задания Ритма, созданные из чата, и правки заданий Ритма сверх `attach_to_session` по явной просьбе владельца вне контракта.
