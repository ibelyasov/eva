# Предпочтения задаются при подключении, пометки объектов — в работе

Настройки JediKit делятся по происхождению.

**Предпочтения** задаются один раз и не возникают из работы с объектами провайдеров: часовой пояс (один на все скиллы), рабочие дни, стиль названий привычек, календарь записи и календари чтения, границы дня, зазор, напоминания Событий, Броней и Распорядка, имя Хранилища Obsidian для ссылок `obsidian://` (`jedikit.notes.vault_name`, без default: не задано — обратная ссылка только читаемым путём, [ADR 0021](0021-provider-back-links.md)). Путь Хранилища — не предпочтение: его задают переменные окружения `WIKI_PATH` и `OBSIDIAN_VAULT_PATH` ([ADR 0016](0016-consumer-boundary.md)). Их значения Потребитель определяет при подключении в диалоге владельца со своим агентом и задаёт декларативно в профильном `config.yaml` Хоста, в `skills.config`. Ключи объявляет навигатор `jedikit` в `metadata.hermes.config`; Потребитель включает его в `skills.auto_load`, поэтому карта скиллов и разрешённые значения всегда есть в контексте. Остальные скиллы читают значения из этого блока и не записывают их ни в `memory`, ни в файлы. Просьбу изменить предпочтение в чате скилл не выполняет: называет ключ и новое значение для Потребителя и, если нужно, применяет его только в текущем разговоре.

**Пометки объектов** — Режимы поддерева Областей и Папок SingularityApp и Области Habitify, выбранные как Ритуалы, с первой привычкой — возникают в работе вместе с объектами. Их пишет скилл-владелец в `memory` по ходу сценария: когда сценарию не хватает пометки, он спрашивает в этот момент с рекомендацией и сохраняет ответ. Отдельного setup в чате нет.

**Приглашения к обзорам** — задания cron Хоста, которые Потребитель создаёт и сопровождает по шаблонам из [README](../../README.md#setup); доставку адресует явно. Скиллы задания не создают и не меняют; фоновый запуск только читает и приглашает ([ADR 0003](0003-no-unattended-writes.md)). Базовый шаблон — одно утреннее сообщение незадолго до Daily open: календарная часть, приглашение к Daily open, в день Weekly — к Weekly, в первый Weekly месяца — ещё к модулю Когда-нибудь, и число экспериментов с наступившей датой обзора. Состав по дате выбирает модель по тексту задания: cron Hermes не выражает «первый такой-то день недели месяца», а день месяца и день недели в нём объединяются через «или». День Weekly и другие значения расписания Потребитель подставляет в текст задания; отдельных ключей для них нет. Отдельное приглашение к Daily close по умолчанию не создаётся.

**Контракт setup** — раздел [README «Setup»](../../README.md#setup): ключи, смысл, рекомендуемое значение или правило его вывода из фактов о человеке, основание с уровнем доказательности, альтернативы и шаблоны заданий. Основания рекомендаций — [досье setup](../../research/setup.md). Агент Потребителя рекомендует, а не спрашивает «когда удобно»; спрашивает только факты, которые знает лишь человек; сначала обсуждает рекомендацию текстом, затем получает одно подтверждение.

## Considered Options

- Хранить все настройки в `memory` и проводить setup в чате: значения зависят от модели в мессенджере, setup превращается в анкету, а расписания нельзя адресовать в нужную тему без участия человека.
- Объявить ключи в каждом провайдерном скилле: обычный `skill_view` Hermes v0.21.6 не подставляет значения `skills.config`; пришлось бы постоянно загружать все полные скиллы с ключами.
- Отдельный маленький скилл настроек: ещё один скилл ради носителя; навигатор и так отвечает за общую карту.
- Задавать пометки объектов декларативно: каждая новая Папка или Ритуал требовали бы деплоя, а ID Областей появляются только после их создания в провайдере.
- `SOUL.md`, файлы контекста или заполненная Потребителем `memory`: смешивают настройки с характером Хоста, зависят от рабочего каталога или делают изменяемое состояние источником декларации.

## Consequences

Hermes печатает значения блока как текст и показывает пустые и ложные значения (`0`, `false`, `[]`, `{}`, `''`) как `(not set)`, поэтому ключи устроены так, что «не задано» и пустое значение совпадают по смыслу. Для незаданного предпочтения действует default, описанный для ключа; если default нет и значение блокирует сценарий, скилл спрашивает его одним `clarify` для текущего разговора и называет ключ, который нужно задать у Потребителя. Ненужное сценарию не спрашивается.

`metadata.hermes.config` несовместим с portable plugin loader, поэтому JediKit подключается только каталогом через `skills.external_dirs`, без plugin manifest ([ADR 0005](0005-hermes-host-connections.md)). Штатных `hermes plugins validate` и `doctor` для такого каталога нет: CI проверяет `git diff --check`, остальное — независимое ревью; валидность frontmatter, security scan и discovery до появления штатной проверки Hermes автоматически не проверяются.

Навигатор загружается всегда, но остаётся справкой, а не обязательным шагом перед каждым запросом ([ADR 0011](0011-navigator-always-loaded.md)). Значения подставляются при создании экземпляра агента Хоста: после изменения `skills.config` нужен новый экземпляр (например, перезапуск gateway). Cron-задание, которому нужны предпочтения, прикрепляет `jedikit` вместе со скиллами сценария. Часовой пояс JediKit и часовой пояс Хоста, по которому считается cron, — разные входы; Потребитель задаёт их согласованно.

`memory` хранит только пометки объектов ([ADR 0006](0006-memory-holds-object-marks.md)). Записи предпочтений в `memory` и задания cron, созданные из чата, вне контракта.
