# `eva-notes` — один переносимый скилл Agent Skills

Хранилище Obsidian владелец ведёт не только из Hermes, но и из агента, открытого в Хранилище: Claude Code, Codex, Gemini CLI, GitHub Copilot, Cursor, OpenCode, Goose. Все они, как и Hermes, читают скиллы формата Agent Skills: каталог с `SKILL.md` (frontmatter `name` и `description`) и файлами, которые модель читает относительно каталога скилла. Поэтому `eva-notes` — один host-нейтральный текст для всех клиентов Agent Skills, включая Hermes, без копий и вариантов под хосты. Остальные пять скиллов Eva остаются скиллами Hermes ([ADR 0005](0005-hermes-host-connections.md)).

**Текст.** Frontmatter — только `name` и `description`. Свои файлы скилл называет путём из каталога скилла — `references/<файл>.md` — и читает их тем же инструментом, которым загружен скилл, с путём файла, а если такого нет — чтением файла по абсолютному пути каталога скилла. Голый относительный путь файловый инструмент разрешил бы от корня Хранилища и прочитал бы чужой файл. Синтаксиса `skill_view` в тексте нет; ожидается, что модель Hermes по этой фразе читает файл через `skill_view(name, file_path)`, — это не проверено. Соседние скиллы — `eva`, `eva-tasks`, `eva-habits`, `grill-me` — текст называет по имени: их загружает инструмент скиллов хоста, а без него модель находит скилл в списке скиллов хоста или в том же каталоге скиллов и читает его `SKILL.md`. Инструменты описаны действиями: прочитать, найти и записать файл, POSIX-оболочка, вопрос владельцу, извлечь страницу. Hermes-специфика — песочница, кэш `web_extract`, `printenv`, встроенные основы — живёт в разделе «Hermes» `references/tools.md`; [`tools.json`](../../skills/eva-notes/tools.json) остаётся контрактом инструментов Hermes ([ADR 0018](0018-notes-over-llm-wiki.md)).

**Корень Хранилища.** Если в окружении агента задана `OBSIDIAN_VAULT_PATH` или `WIKI_PATH`, корень берётся из неё, и обе, если заданы, указывают на один путь — так в Hermes ([ADR 0016](0016-consumer-boundary.md)). Иначе корень — рабочий каталог агента, если в нём есть `.obsidian/`. Иначе скилл останавливается и просит открыть агента в корне Хранилища. Это два штатных способа работы, а не запасной путь. Основам `llm-wiki` и `obsidian` корень передаётся явно: их пути по умолчанию `~/wiki` и `~/Documents/Obsidian Vault` не используются. `SCHEMA.md` и `AGENTS.md` Хранилища скилл всегда читает явно: `SCHEMA.md` сам не загружает ни один хост, а `AGENTS.md` хосты подхватывают только из рабочего каталога и не все — Gemini CLI без настройки `context.fileName` и Claude Code при соседнем `CLAUDE.md` его не берут.

**Отдельная установка.** В клиенте Agent Skills ставится только `eva-notes` с копиями основ — без навигатора `eva`, Журнала Eva, Ритма, Инициативы, Возвратов и cron. Всё лежит в самом Хранилище. `eva-notes` — в `<Хранилище>/.agents/skills/eva-notes/`: этот каталог читают Codex, Gemini CLI, Copilot, Cursor, OpenCode и Goose. Claude Code `.agents/skills` не читает, поэтому для него отдельный шаг создаёт симлинк `<Хранилище>/.claude/skills/eva-notes` → `../../.agents/skills/eva-notes`. Основы `llm-wiki` и `obsidian` — неизменённые копии `SKILL.md` из закреплённого commit Hermes `818c13be1dc4fd28987e1e881a9408224afd4535` с копией MIT-лицензии Hermes рядом — лежат в `<Хранилище>/.agents/eva-notes-bases/{llm-wiki,obsidian}/`, вне каталогов скиллов: клиенты не видят их как скиллы. Основу `eva-notes` находит так: в Hermes — встроенный скилл по имени; иначе — `SKILL.md` копии по пути от корня Хранилища; копии нет — скилл с этим именем, если хост его даёт; нет ни того, ни другого — называет основу и рекомендует установку. Eva основы не распространяет и метод вики не копирует ([ADR 0018](0018-notes-over-llm-wiki.md)). Каталоги `.agents/` и `.claude/` исключены из вики, lint, `index.md` и разбора, файлы скиллов и основ `eva-notes` не меняет.

Установку выполняет Установщик — агент владельца в клиенте Agent Skills. Владелец даёт ему ссылку на опубликованную версию Eva и просит «установи только eva-notes». Установщик идёт от `README.md` к разделу отдельной установки в [`SETUP.md`](../../SETUP.md#10-eva-notes-на-любом-агенте-agent-skills). Ссылка без тега означает последний релиз, ссылка на ветку или commit — вопрос владельцу о теге; без опубликованного релиза установка не начинается. Инструкцию Установщик берёт из `SETUP.md` того же тега, что и файлы: если в нём нет раздела отдельной установки, эта версия её не поддерживает, и Установщик останавливается и говорит владельцу, что нужна более новая версия. Он ставит `eva-notes` из тега и основы из закреплённого commit Hermes, ничего в Хранилище не удаляет — прежнюю версию переносит во временный каталог вне Хранилища, — проверяет результат и обновляет установку той же процедурой. Своего установщика-скрипта у Eva нет ([ADR 0004](0004-no-custom-code.md)).

**Без соседей.** `eva-notes` сам замечает, каких скиллов нет. Без `eva` он не пишет в `Eva/`, только исключает её из вики. Без `eva-tasks` обязательство из «запиши …» становится строкой-задачей `- [ ]` в заметке дня; с `eva-tasks` оно передаётся ему, как в Hermes ([ADR 0020](0020-ideas-in-daily-notes.md)). Предпочтения скилл читает из блока `eva`, если Хост его даёт. Иначе Предпочтения не задаются: дата и время — местные для машины агента, а ссылка `obsidian://` не пишется ([ADR 0017](0017-declarative-preferences.md), [ADR 0021](0021-provider-back-links.md)).

**Вопрос владельцу.** Если Хост даёт карточку выбора (`clarify` в Hermes), вопрос задаётся ею, иначе обычным сообщением в чате. Timeout, пропуск и молчание — не согласие ([ADR 0019](0019-vault-write-consent.md)). Без инструмента извлечения страницы ссылка захватывается источником с `capture: partial`; ошибка или пустой ответ инструмента — во Входящие хранилища с `capture: failed`.

**Hermes.** В Hermes `eva-notes` подключается, как остальные скиллы, каталогом `skills/` закреплённой ревизии в `skills.external_dirs` ([ADR 0005](0005-hermes-host-connections.md)), а основы — встроенные скиллы Hermes. Хранилище не делается доверенным проектом Hermes (`hermes skills trust`): проектные скиллы в Hermes важнее всех остальных уровней, и копия `eva-notes` из `.agents/skills` Хранилища перекрыла бы закреплённую ревизию. Каталог `.agents/eva-notes-bases/` Hermes не сканирует и `eva-notes` в Hermes его не читает.

## Considered Options

- Отдельные копии или варианты текста под каждый хост: несколько источников одного поведения расходятся. Формат Agent Skills общий, а различия хостов умещаются в один раздел справочника.
- Корнем Хранилища считать только рабочий каталог: в Hermes Хранилище смонтировано в песочницу, и его путь задают переменные окружения, а рабочий каталог разговора может быть другим.
- `.claude/skills` основным каталогом: его читают 5 из 8 целевых клиентов, но не Codex, Gemini CLI и Hermes. `.agents/skills` читают 7 из 8, а Claude Code получает скилл через симлинк.
- Основы рядом с `eva-notes` в `.agents/skills` как обычные скиллы: клиент выбирал бы их сам по запросам вроде «найди в заметках» или «добавь в вики» в обход `eva-notes` — без Плана сущностей, правил согласия и русских папок, — а без переменных окружения они писали бы вне Хранилища, в `~/wiki` и `~/Documents/Obsidian Vault`. Загрузки скилла по имени у Codex и Goose нет, так что `eva-notes` всё равно читал бы их `SKILL.md` по пути.
- Вшить `llm-wiki` в `eva-notes`: копия метода отстаёт от upstream и делает Eva распространителем чужого текста ([ADR 0018](0018-notes-over-llm-wiki.md)). Установщик и так кладёт основы рядом из закреплённого commit.
- Инструкция установки с default branch при файлах из тега: инструкция и файлы разных версий расходятся, и Установщик поставил бы версию, которую инструкция не описывает.
- Ставить навигатор `eva` в Отдельной установке: он нужен Журналу, Инициативе и Предпочтениям из `skills.config`, а вне Hermes их нет. Без провайдерных скиллов и cron навигатор был бы пустой картой.

## Consequences

Статикой не проверяются и остаются слоями живой эксплуатации:

- загрузка скилла и чтение `references/` в каждом клиенте, в том числе выбор моделью Hermes `skill_view` по нейтральной фразе;
- чтение копий основ по пути и их применение моделью;
- поведение дублей: Copilot, Cursor, OpenCode и Goose читают и `.agents/skills`, и `.claude/skills`, поэтому после шага для Claude Code могут увидеть `eva-notes` дважды;
- обход скрытых симлинков индексатором Obsidian;
- вердикт `skills_guard` Hermes для текста `eva-notes`;
- поведение моделей по нейтральным формулировкам и переопределениям основ.

Модельных прогонов нет ([ADR 0004](0004-no-custom-code.md)).

`OBSIDIAN_VAULT_PATH` или `WIKI_PATH`, заданные в окружении агента для других инструментов, важнее рабочего каталога: `eva-notes`, открытый в одном Хранилище, работал бы с другим. Установщик проверяет переменные и предупреждает владельца, если они указывают не на это Хранилище.

В Hermes без блока навигатора дата заметки дня берётся по поясу машины агента — в песочнице обычно UTC, — поэтому навигатор там подключается через `skills.auto_load` ([ADR 0011](0011-navigator-always-loaded.md)).

Команды установки и скилла — POSIX: в Windows без Git Bash или WSL их нужно выполнять в такой оболочке. Прежняя версия при обновлении лежит во временном каталоге, который система может очистить; долгую историю версий даёт Git Хранилища.

Obsidian Sync не переносит папки на «.», кроме `.obsidian`. Self-hosted LiveSync переносит их только с отдельной Hidden File Sync. Поэтому на другом устройстве установку повторяют или переносят `.agents/` и `.claude/` Git Хранилища; Git хранит симлинк как ссылку. Obsidian не показывает папки на «.», поэтому скиллов и основ в проводнике Obsidian не видно.

Скиллы и основы в Хранилище, открытом агенту на запись, защищены от правки только текстом скилла. Hermes не требует approval на запись `SKILL.md` и сам предлагает модели `skill_manage` для починки скиллов. Approval записи в `AGENTS.md` Хранилища — свойство Hermes ([ADR 0019](0019-vault-write-consent.md)); в других клиентах эту запись ограничивают только права клиента и текст скилла.

Смена commit Hermes для основ — правка `SETUP.md` вместе со сверкой переопределений ([ADR 0018](0018-notes-over-llm-wiki.md)); у владельца Установщик повторяет ту же процедуру. Публикация версии остаётся решением владельца: установка берёт `eva-notes` и инструкцию из тега опубликованной версии, а без опубликованной версии с разделом отдельной установки не начинается. Основания — [досье клиентов Agent Skills](../../research/platforms/agent-skills.md) и [досье Hermes](../../research/platforms/hermes.md).
