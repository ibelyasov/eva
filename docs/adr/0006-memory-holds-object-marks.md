# В памяти агента только пометки объектов

Память Hermes хранит только пометки объектов провайдеров, которые возникают в работе: Режимы поддерева Областей и Папок SingularityApp и ID Областей Habitify, выбранных как Ритуалы, с `habitId` первой привычки каждого Ритуала — API не хранит порядок, а время старта Ритуала — напоминание первой привычки. Это решения пользователя об объектах, не копия состояния провайдеров. Предпочтения — часовой пояс, рабочие дни, стиль названий привычек и настройки календаря — задаёт Потребитель в `skills.config`, и в памяти их нет ([ADR 0017](0017-declarative-preferences.md)). `jedikit-notes` память не использует: правила оформления Хранилища живут в его `SCHEMA.md` ([ADR 0019](0019-vault-write-consent.md)).

Состояние задач, привычек, Ритуалов, календаря и обзоров не хранится: вчерашние хвосты daily open берёт из просроченных задач провайдера, дата следующего обзора эксперимента записана в его плане, пропущенный weekly не отслеживается — приглашает расписание. План дня и выполнение Ритуала каждый раз читаются из провайдеров. Хранение дат проведённых обзоров и восстановление по ним усложнили бы обзоры сильнее, чем дали пользы. Представление Ритуала областью и ограничения его интерпретации описаны в [досье ритуалов](../../research/habits/rituals.md).

## Consequences

Пометку записывает скилл-владелец по ходу сценария: когда сценарию не хватает пометки, он спрашивает в этот момент с рекомендацией и сохраняет ответ по своим правилам записи. Пометки сохраняются только инструментом Hermes `memory` с `target="memory"`: одна компактная запись на скилл — `JediKit tasks:` с Режимами поддерева и `JediKit habits:` с Ритуалами; у `jedikit-calendar`, `jedikit-planning`, `jedikit-notes` и `jedikit` записей в памяти нет. Новая запись — `add(content)`, изменение — `replace(old_text, content)`, который заменяет запись целиком. Отдельного чтения нет: текущие записи видны в контексте памяти. Лимит около 2200 символов общий для всех записей памяти профиля. Ответ `done:true` означает, что запись применена; `staged:true` с `pending_id` — что она ждёт одобрения (`/memory pending`) и не считается сохранённой.

Файлы скиллов JediKit — закреплённая ревизия пакета, а не хранилище пользователя; у владельца они лежат в неизменяемом Nix store. Поэтому пометки, предпочтения и состояние не записываются в `SKILL.md`, `references/` или файлы рядом — ни через `skill_manage`, ни файловыми инструментами, — даже если описание инструмента `memory` советует хранить предпочтения в скилле. Файлового fallback нет ([досье Hermes](../../research/platforms/hermes.md)).
