# Фоновые запуски пишут только в Журнал Eva

Расписание Eva — задания cron Hermes. Задания Ритма — Рефлексию, утро, Дневную проверку и закрытие дня — Потребитель создаёт и сопровождает по шаблонам [`SETUP.md`](../../SETUP.md) и сам адресует их доставку ([ADR 0017](0017-declarative-preferences.md), [ADR 0022](0022-eva-journal-and-initiative.md)); prompt такого задания начинается маркером `[расписание eva]`. Задания Ритма Eva не создаёт и не удаляет и по своей инициативе не меняет; по явной просьбе владельца она выставляет у названного задания Ритма только `attach_to_session`, потому что CLI Hermes его не задаёт. Сама она ставит себе только Возвраты — разовые задания с маркером `[возврат eva]`.

Фоновый запуск читает провайдеров, Журнал Eva и диалоги (`session_search`), пишет только в Журнал — Наблюдения, Практики, Ленту — и ставит Возвраты. Провайдерам, в заметки Хранилища и в `memory` он не пишет, Брони не создаёт. Найденные дубли тегов, пустые разделы, проекты без шага и прочая гигиена становятся Наблюдениями с предлагаемым решением и выполняются в разговоре по правилам записи ([ADR 0014](0014-confirmations.md)). Владелец хотел часть обслуживания делать в фоне без вопросов, но нет данных, что агент надёжно угадывает смысл чужих категорий, а ошибочное фоновое объединение или удаление молча ломает систему пользователя. Журнал — служебная зона Eva: ошибочная запись в нём ничего не ломает у провайдеров, владелец видит и правит её, а откат даёт Git Хранилища.

## Consequences

В cron Hermes `clarify` и `messaging` выключены всегда, поэтому фоновый запуск не может получить согласие и ни о чём не спрашивает: ответ владельца на его сообщение продолжает разговор, где действуют обычные правила записи ([ADR 0019](0019-vault-write-consent.md)). `cronjob` в cron выключен по умолчанию и включается настройкой Потребителя `cron.allow_agent_scheduling: true`; без неё фоновый запуск Возврат не ставит, а оставляет Наблюдение со сроком, которое поднимет Дневная проверка. Разовое расписание — вида `in 2h` или ISO-время. Нечего сказать — ответ `[SILENT]`, доставка подавляется. Поля timezone у задания нет: время считается по `HERMES_TIMEZONE`, затем по `timezone` профиля Hermes. Задание, запуск и доставка — разные результаты. Фоновому запуску нужны чтения провайдеров, `file` для Журнала, `session_search`, `cronjob` и `skills` в toolsets cron (`platform_toolsets.cron`) и прикреплённые к заданию `eva` и скиллы сценария — это настройка cron Хоста, которую делает Потребитель; скилл не расширяет toolsets cron сам.
