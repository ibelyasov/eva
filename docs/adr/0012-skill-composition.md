# У каждого действия один ответственный скилл

`jedikit-tasks` отвечает за задачи, проекты, Inbox и обзоры в SingularityApp; `jedikit-habits` — за эксперименты, отметки, области и Ритуалы в Habitify; `jedikit-calendar` — за вид календарей, События и Распорядок в Google Calendar; `jedikit-planning` — за План дня, вместимость Фокус-листа и Брони; `jedikit-notes` — за Хранилище Obsidian: вики знаний, дневник, захват и ответы по базе ([ADR 0018](0018-notes-over-llm-wiki.md)); `jedikit` — всегда загруженный навигатор: карта скиллов, справка по запросу, карта команд, словарь и объявление ключей предпочтений ([ADR 0017](0017-declarative-preferences.md)). У каждого действия один явный ответственный. Перед записью в чужого провайдера или в Хранилище скилл загружает скилл-владельца по голому имени через `skill_view` и читает его `references/write-policy.md` через `skill_view(..., file_path=…)`, затем применяет эти правила; чужие правила не пересказывает. Это сохраняет один источник политики для каждой операции ([досье композиции](../../research/agents/skill-composition.md)).

Ссылки идут от `jedikit-planning` и `jedikit` к провайдерным скиллам. Провайдерные скиллы и `jedikit-notes` не ссылаются на `jedikit-planning` и `jedikit` в инструкциях; `description` может назвать соседний скилл только для различения при выборе, например «План дня с задачами ведёт jedikit-planning». Связку Daily open → План дня показывает навигатор. Между провайдерными скиллами и `jedikit-notes` допускаются явные передачи: `jedikit-tasks` → `jedikit-calendar` для встречи из Inbox, `jedikit-habits` → `jedikit-calendar` для смены времени Ритуала с блоком Распорядка, любой скилл → `jedikit-tasks`, если запрос является задачей. `jedikit-tasks` → `jedikit-notes` переносит Идею и Справку из Inbox в Хранилище ([ADR 0008](0008-cancel-instead-of-delete.md)). `jedikit-notes` → `jedikit-habits` или `jedikit-tasks` читает ID привычки или проекта для Заметки и записывает у провайдера обратную ссылку на неё ([ADR 0021](0021-provider-back-links.md)). «Запиши …» без явного места распределяется по смыслу: обязательство — в Inbox через `jedikit-tasks`; идея, мысль, ссылка, файл или справка — в Хранилище через `jedikit-notes`; неясное — в Inbox ([ADR 0020](0020-ideas-in-daily-notes.md)). Передача не считается состоявшейся без фактической загрузки скилла через `skill_view`. Формулировка «для операций SingularityApp/Habitify используй …» ограничивает операции конкретного провайдера и не запрещает композицию.

## Consequences

Хранилище в этих правилах — такое же место записи, как провайдер; Read-back Хранилища — `read_file` записанного файла, а состав разбора утверждается Планом сущностей ([ADR 0019](0019-vault-write-consent.md)). Полная явная команда на два провайдера выполняется в обоих последовательно без дополнительного подтверждения, с Read-back после каждой записи, остановкой на первой ошибке и отчётом applied/unverified/unapplied, без автоматического отката. Исключение для безвозвратных операций Habitify задаёт [ADR 0014](0014-confirmations.md). Набор изменений на двух провайдерах, собранный агентом, требует одного общего Preview и одного подтверждения, а затем того же порядка исполнения. При недоступности скилла-владельца или его инструментов агент называет невыполненную часть, не имитирует передачу и результат.
